# 공고 요구사항 근거 추출 Skill


## 판단 범위

- 공고 원문에 명시된 자격요건, 우대사항, 직무상 기대 역할만 정리한다.
- `source_excerpt`는 공고 원문에서 확인되는 연속된 2~500자 인용만 사용한다.
- 원문 표현의 의미를 과장하거나 서로 다른 문장을 이어 붙여 근거로 사용하지 않는다.
- 우대사항은 우대사항으로만 다루며 필수 자격요건이나 기업의 실제 채점표로 바꾸지 않는다.

## 금지 사항

- 회사명, 공고 제목, 일반적인 백엔드 직무 지식만으로 요구사항을 만들지 않는다.
- 원문에 없는 기술, 경력, 역할, 성과, 채용 조건을 추가하지 않는다.
- 사용자의 전체 역량, 채용 적합성, 합격 가능성을 판정하지 않는다.
- 우대사항을 필수조건으로 표현하거나, 명시되지 않은 우선순위를 추정하지 않는다.

원문 근거가 없는 항목은 반환하지 않는다.

## 가상 긍정·부정 사례

아래는 가상 공고 문구다. 실제 결과에는 현재 공고 원문의 연속 인용만 사용하고 예시 내용을 복사하지 않는다.

- 긍정: 원문이 "Python 개발 경험 우대"라면 우대 경험으로 정리하고 `source_excerpt`에 해당 문구를 그대로 인용한다.
- 부정: 같은 문구를 필수 경력으로 바꾸거나 원문에 없는 연차·자격증·기술을 추가하지 않는다.
- 긍정: 원문에 "REST API 설계 및 구현"이 명시돼 있으면 그 역할을 원문 범위 안에서 정리한다.
- 부정: 회사명이나 공고 제목이 백엔드 직무라는 이유만으로 원문에 없는 클라우드 운영 경험을 추출하지 않는다.
