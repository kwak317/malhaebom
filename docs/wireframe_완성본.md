# 말해봄 프론트엔드 와이어프레임 완성본

> **상태: historical snapshot.** 초기 프론트엔드 화면 설계를 보존한 문서이며 현재 MVP 범위나 구현 계약의 canonical이 아니다. 현재 제품 범위는 [CONSTRAINTS](CONSTRAINTS.md), 연습 설정·직접 입력 질문 계약은 [practice-setup-and-question-tts Spec](specs/practice-setup-and-question-tts.md)을 따른다.
> 아래의 “현재 범위”, “제외/보류” 표현은 작성 당시 기준이며 현재 상태로 해석하지 않는다.
> 작성 방식: 화면 구조, UI 요소, 버튼, 상태, 화면 이동을 정의한다. 디자인 색상과 세부 스타일은 이 문서에서 결정하지 않는다.
> 완성본 원칙: 첫 화면의 왼쪽 `이용안내` 카드는 고정하고, 오른쪽 카드에서 질문 선택 → 마이크 확인 → 연습 시작을 상태 전환으로 처리한다. `연습 시작하기`를 누른 뒤에만 녹음 화면으로 이동한다.
> 현재 범위: 첫 화면 → 질문 선택 → 마이크 확인 → 녹음 → 녹음 완료 → 분석 → 분석 결과 → TTS 피드백 예시 → 재녹음 → 1차/2차 비교
> 제외/보류: 직접 작성 질문, 답변 구성 분석, 음량/억양 분석, 강한 자동 개선 판정은 현재 MVP 와이어프레임에 포함하지 않는다.

## 0~2. 연습 시작 페이지의 공통 구조

### 핵심 결정

첫 화면에 진입하면 오른쪽 카드에서 바로 질문 목록을 보여준다. 질문 선택과 마이크 상태 확인은 서로 다른 URL 페이지가 아니며, 하나의 `practice` 페이지 안에서 오른쪽 카드의 상태만 바뀐다. 왼쪽 `이용안내` 영역은 모든 상태에서 고정한다.

```text
/practice
  ├─ landing       첫 화면 + 질문 미선택
  ├─ landing       질문 선택 완료
  ├─ landing       마이크 확인 중/완료
  └─ recording     연습 시작 후 녹음 화면
```

헤더·이용안내 카드·페이지 컨테이너는 유지하고, 오른쪽 카드의 본문과 하나의 메인 CTA만 상태에 맞게 갱신한다. 브라우저 뒤로가기는 페이지를 이탈시키기보다 오른쪽 카드의 이전 상태로 돌아가는 방향을 우선한다.

공통 상태 계약:

```text
PracticeSession
- step: landing | recording | recordComplete | analyzing | firstResult | secondRecording | secondResult | compare
- entryState: questionNotSelected | questionSelected | micCheckReady | micChecking | micGranted | micDenied
- activeQuestionId: string | null
- questionType: preset | null
- micState: unknown | checking | granted | denied
```

공통 동작:

- `activeQuestionId`가 없는 상태에서는 마이크 확인 상태로 바뀔 수 없다.
- `activeQuestionId`가 바뀌면 마이크 상태는 `unknown`으로 초기화한다.
- `questionNotSelected → questionSelected → micChecking → micGranted`는 같은 페이지의 오른쪽 카드 안에서 진행한다.
- 녹음 전환 시점에만 다음 단계인 `recording`으로 바뀐다.
- 단계가 바뀌어도 선택한 질문은 세션에 유지한다.

## 0. 첫 화면

### 화면 목적

사용자가 서비스의 목적을 이해하면서 바로 질문을 고를 수 있는 첫 화면이다. 왼쪽 `이용안내` 카드는 고정되어 계속 보이고, 오른쪽 카드는 처음부터 질문 선택 상태로 표시한다.

### 페이지 구조

- 페이지 경로: `/practice`
- `PracticeStep`: `landing`
- `EntryPracticeState`: `questionNotSelected`
- 고정 영역: 서비스명 헤더, `이용안내` 카드
- 변경 영역: 오른쪽 `질문 선택` 카드

### 필요한 UI 요소

- 상단 헤더
  - 왼쪽: 말해봄 로고, 서비스명 `말해봄`
  - 오른쪽: `연습하기`, `연습 기록`, `로그인 / 회원가입`
  - 현재 화면에 따라 활성 탭을 시각적으로 구분한다.
    - 첫 화면 및 연습 진행 흐름: `연습하기` 활성
    - 연습 기록 목록 및 결과 조회: `연습 기록` 활성
- 고정 왼쪽 카드: `이용안내`
  - 제목: `AI 면접 전달력 코치`
  - 설명: `답변은 준비됐어요. 이제 말하는 방식을 다듬어볼까요?`
  - 안내: `60초 답변을 녹음하면 말속도, 긴 침묵, 음·어와 반복 표현을 분석하고 같은 답변의 전달 예시를 들려드려요.`
  - 원칙: `답변 내용은 바꾸지 않아요.`
  - 개인정보 안내: `녹음은 세션 종료 후 삭제돼요.`
  - 흐름: `1. 답변 녹음 → 2. 전달력 분석 → 3. 듣고 재연습`
- 오른쪽 카드 제목: `어떤 질문으로 시작할까요?`
- 오른쪽 카드 설명: `질문을 선택해 주세요.`
- 오른쪽 카드 메인 CTA 하나: `이 질문으로 시작하기` (질문 미선택 시 비활성)
- 헤더 메뉴: `연습하기`, `연습 기록`, `로그인 / 회원가입`을 항상 표시한다.
- `연습하기`: 기존 첫 화면으로 이동하고 질문 미선택 상태에서 새 연습을 시작할 수 있다. 완료된 연습 기록은 삭제하지 않는다.
- `연습 기록`: 기존 연습 기록 목록 화면으로 이동한다.
- `로그인 / 회원가입`: 기존 정의를 유지한다.
- 기존 SDD의 최대 24시간 보관 및 삭제 정책은 그대로 적용한다.

`로그인 / 회원가입`은 상세 인증 화면을 이 문서에서 정의하지 않지만, 첫 화면 헤더에서는 비활성 텍스트가 아닌 활성 메뉴 항목으로 표시한다.

### 상호작용

#### 질문 선택

- 동작: 질문 목록에서 한 항목을 선택하면 `activeQuestionId`를 저장하고 `entryState=questionSelected`로 변경한다.
- 페이지 이동: 없음. `/practice` 유지.
- 포커스: 질문 목록 제목 또는 첫 번째 질문 카드로 이동한다.

#### 연습 기록

- 동작: 현재 탭 세션의 기록 화면으로 이동한다.
- 예외: 기록이 없으면 빈 상태를 표시한다.

### 상태별 처리

- 기본: 왼쪽 `이용안내` 카드는 고정하고, 오른쪽에 10개 질문 목록과 비활성 CTA를 표시한다.
- 세션 기록이 있음: CTA 문구는 그대로 두고, `연습 기록`에 기록 존재 여부만 보조 표시할 수 있다.
- 세션 기록이 없음: 기록 메뉴는 숨기지 않는다.

## 1. 첫 화면 내부 상태: 질문 선택

### 화면 목적

첫 화면에 처음 들어왔을 때의 기본 상태다. 오른쪽 카드에서 기본 질문 10개를 선택하며, 왼쪽 `이용안내` 카드는 바뀌지 않는다. 질문을 선택하기 전과 후에 같은 메인 CTA의 활성 상태만 바뀐다. 직접 작성 질문은 제공하지 않는다.

### 필요한 UI 요소

- 카드 내부 상태: `questionNotSelected` 또는 `questionSelected`
- 제목: `어떤 질문으로 시작할까요?`
- 기본 질문 카드 목록
  - `1분 자기소개를 해주세요.`
  - `이 직무에 지원한 이유는 무엇인가요?`
  - `팀원과 갈등을 해결한 경험이 있나요?`
  - 총 10개 질문을 제공하며, 카드 내부에서 스크롤할 수 있다.
- 선택된 카드의 시각·텍스트 상태
- 선택 요약: `선택한 질문`
- 하단 메인 CTA: `이 질문으로 시작하기`
  - 질문 미선택: 비활성
  - 질문 선택: 활성

### 질문 카드 상태

```text
QuestionCardState
- default
- selected
- focus
```

- `default`: 선택되지 않은 카드
- `selected`: 라디오 선택 상태와 선택 표시를 함께 제공
- `focus`: 키보드 포커스가 보이는 상태
- 카드는 한 번에 하나만 선택할 수 있다.

질문 데이터 계약:

```text
Question
- questionId
- category
- questionText
- shortGuide
```

기본 질문 예시:

```text
01 | 자기소개   | 1분 자기소개를 해주세요.                | 핵심 경험과 강점을 간결하게 전달해 보세요.
02 | 지원동기   | 이 직무에 지원한 이유는 무엇인가요?         | 지원 직무와 자신의 경험을 연결해 보세요.
03 | 협업경험   | 팀원과 갈등을 해결한 경험이 있나요?         | 상황·행동·결과 순서로 말해 보세요.
04 | 문제해결   | 어려운 문제를 해결한 경험을 말해 주세요.    | 문제와 해결 과정을 구체적으로 설명해 보세요.
05 | 기술선택   | 사용해 본 기술을 선택한 이유는 무엇인가요?  | 선택 기준과 실제 사용 경험을 말해 보세요.
06 | 실패경험   | 실패하거나 아쉬웠던 경험이 있나요?          | 배운 점과 이후 행동을 중심으로 말해 보세요.
07 | 강점       | 본인의 가장 큰 강점은 무엇인가요?           | 면접 직무와 연결되는 사례를 덧붙여 보세요.
08 | 약점       | 보완하고 싶은 점은 무엇인가요?              | 개선을 위해 한 행동을 함께 말해 보세요.
09 | 프로젝트   | 가장 기억에 남는 프로젝트를 소개해 주세요.   | 본인의 역할과 결과를 분명히 설명해 보세요.
10 | 목표       | 입사 후 어떤 개발자가 되고 싶나요?          | 단기 목표와 성장 방향을 말해 보세요.
```

### 상호작용

#### 질문 카드 선택

- 동작: `activeQuestionId`와 `questionType=preset`을 저장한다.
- 화면: 같은 페이지 유지, 선택 요약과 `이 질문으로 시작하기` 버튼을 활성화한다.
- 마이크 상태: 질문이 바뀌면 `micState=unknown`으로 초기화.

#### 이 질문으로 시작하기

- 활성 조건: `activeQuestionId !== null`
- 동작: `entryState=micCheckReady`로 변경하고, 오른쪽 카드의 질문 목록과 선택 질문을 유지한다. 메인 CTA 문구만 `마이크 확인`으로 변경한다.
- 페이지 이동: 없음.

### 오류 및 접근성

- 질문이 선택되지 않은 상태에서 메인 CTA는 비활성화한다.
- 오류 문구는 버튼만 색으로 구분하지 않고 텍스트로 제공한다.
- 질문 카드는 키보드로 이동·선택할 수 있고, 선택 상태를 보조기술에 전달한다.
- 질문 목록에는 그룹 제목을 제공한다.

## 2. 첫 화면 내부 상태: 마이크 상태 확인

### 화면 목적

사용자가 `이 질문으로 시작하기`를 누른 뒤 같은 첫 화면의 오른쪽 카드에서 마이크 권한과 사용 가능 여부를 확인한다. 왼쪽 `이용안내` 카드와 헤더는 유지한다. 권한 확인 전 메인 CTA는 `마이크 확인`이고, 권한이 허용된 뒤 같은 CTA 영역이 `연습 시작하기`로 바뀐다. 이 버튼을 눌러야 처음으로 녹음 화면으로 이동한다.

### 필요한 UI 요소

- 카드 내부 상태: `micCheckReady | micChecking | micGranted | micDenied`
- 선택한 질문 카드
- 녹음 조건
  - 최소 5초
  - 최대 60초
  - 녹음 종료 후 분석 전 원본 확인 가능
- 마이크 권한 안내
- 상태별 안내 영역
- 하단 메인 CTA 하나
  - `마이크 확인`: 권한 확인 전
  - `확인 중...`: 권한 요청 중, 비활성
  - `연습 시작하기`: 마이크 준비 완료 후 활성
  - `다시 확인`: 권한 거부 또는 오류
- 선택한 질문을 바꾸려면 질문 목록의 다른 항목을 선택한다. 별도의 추가 버튼은 두지 않는다.

### 마이크 상태와 화면 계약

```text
MicState
- unknown   아직 권한 확인 전
- checking  브라우저 권한 요청 중
- granted   녹음 시작 가능
- denied    권한 거부 또는 사용할 수 없음
```

### 상호작용

#### 마이크 확인

- 표시 조건: `entryState=micCheckReady` 또는 `entryState=micDenied`
- 동작: `entryState=micChecking`, `micState=checking`으로 바꾸고 브라우저 권한 요청을 시작한다.
- 성공: `entryState=micGranted`, `micState=granted`로 변경하고 메인 CTA를 `연습 시작하기`로 바꾼다.
- 실패: `entryState=micDenied`, `micState=denied`로 변경하고 메인 CTA를 `다시 확인`으로 바꾼다.
- 중복 클릭: `checking` 동안 버튼을 비활성화한다.

#### 확인 중...

- 표시 조건: `entryState=micChecking` 또는 `micState=checking`
- 동작: 권한 확인이 끝날 때까지 비활성 상태를 유지한다.
- 추가 버튼: 표시하지 않는다.

#### 연습 시작하기

- 표시/활성 조건: `micState=granted`
- 동작: 첫 번째 Attempt를 준비하고 `step=recording`으로 변경한다.
- 페이지 이동: 이 버튼을 누를 때 처음으로 녹음 중 화면으로 이동한다.
- 권한 재확인: 시작 직전에 권한이 해제되면 녹음을 시작하지 않고 `denied` 안내를 표시한다.

### 상태별 화면 처리

#### micCheckReady

```text

```

#### pending

```text

보조 안내: 브라우저에 표시된 권한 요청을 허용해 주세요.
```

#### granted

```text
안내: 마이크가 준비되었습니다.
표시: ✓ 마이크 준비 완료

```

#### denied

```text

[다시 확인] 활성
```

### 0~2 단계 완료 조건

- Given `/practice`에 진입했을 때, When 사용자가 질문을 선택하지 않으면, Then 오른쪽 카드에 질문 목록과 비활성 `이 질문으로 시작하기`가 표시된다.
- Given 질문을 선택했을 때, When 사용자가 `이 질문으로 시작하기`를 누르면, Then URL 이동 없이 같은 오른쪽 카드의 메인 CTA가 `마이크 확인`으로 바뀌고 질문이 유지된다.
- Given `entryState=micCheckReady`일 때, When 사용자가 `마이크 확인`을 누르면, Then 같은 CTA가 비활성 `확인 중...`으로 바뀐다.
- Given `micState=granted`일 때, When 사용자가 오른쪽 카드의 `연습 시작하기`를 누르면, Then 처음으로 `step=recording` 화면으로 이동한다.
- Given `micState=denied`일 때, When 사용자가 녹음 시작을 시도하면, Then 녹음은 시작되지 않고 권한 안내가 유지된다.

### 오류 상태 예시

오류가 발생해도 별도 페이지로 이동하지 않는다. 왼쪽 서비스 소개 영역과 선택한 질문은 유지하고, 오른쪽 카드의 안내 문구와 메인 CTA만 오류 상태에 맞게 변경한다.

#### `micDenied` · 마이크 권한 거부

```text
안내: 마이크 권한이 필요해요.
브라우저 설정에서 마이크 사용을 허용한 뒤 다시 확인해 주세요.
[다시 확인]
```

#### `micUnavailable` · 마이크 장치를 찾을 수 없음

```text
안내: 사용할 수 있는 마이크를 찾지 못했어요.
마이크가 연결되어 있는지 확인한 뒤 다시 시도해 주세요.
[다시 확인]
```

#### `micCheckError` · 마이크 확인 중 오류

```text
안내: 마이크 상태를 확인하지 못했어요.
잠시 후 다시 시도해 주세요.
[다시 확인]
```

기술 오류 코드나 내부 예외 메시지는 사용자에게 표시하지 않는다.

## 3~4. 녹음 페이지

### 화면 목적

첫 화면에서 `연습 시작하기`를 누른 뒤 처음 이동하는 녹음 페이지다. `ready`, `recording`, `paused`, `completed`는 각각 별도 페이지가 아니라 같은 녹음 페이지 안에서 `RecordingState`에 따라 내용만 변경한다.

```text
PracticeStep
- recording
- secondRecording

RecordingState
- ready
- recording
- paused
- completed
```

### 공통 레이아웃

녹음 페이지는 항상 다음 3개 영역을 유지한다.

```text
┌────────────────────────────────────────────┐
│ 1. 선택한 질문                             │
├────────────────────────────────────────────┤
│                                            │
│ 2. 현재 상태에 따른 안내 / 녹음 정보       │
│                                            │
├────────────────────────────────────────────┤
│ 3. 현재 상태에 따른 버튼                   │
└────────────────────────────────────────────┘
```

#### 1번 영역: 선택한 질문

- `선택한 질문` 라벨과 선택한 질문 문장을 표시한다.
- 예: `"1분 자기소개를 해주세요."`
- `ready`, `recording`, `paused`, `completed` 모든 상태에서 동일하게 유지한다.
- 질문을 다시 선택하거나 바꾸는 기능은 녹음 페이지에 두지 않는다.

#### 2번 영역: 상태별 안내와 녹음 정보

- `ready`: 시작 전 따뜻한 안내 문구
- `recording`: 음성 파형, 현재 시간, 최대 60초
- `paused`: 일시정지 상태와 재개 안내, 현재 시간
- `completed`: 녹음 완료, 총 시간, 재생 정보

#### 3번 영역: 상태별 버튼

- `ready`: `녹음 시작하기`
- `recording`: `일시정지`, `그만하기`
- `paused`: `계속 녹음하기`, `그만하기`
- `completed`: `다시 녹음`, `분석하기`

### 상태 1: 녹음 준비 (`ready`)

#### 화면 목적

사용자가 긴장하지 않고 답변을 시작할 수 있도록 녹음 조건과 짧은 안내를 제공한다.

#### 2번 영역 문구

```text
준비되셨다면 편하게 시작해 주세요.

답변은 5초 이상, 최대 60초까지 녹음할 수 있어요.

완벽하게 말하려 하지 않아도 괜찮아요.
평소처럼 자연스럽게 답해 주세요.
```

필수로 전달하는 내용은 최소 5초, 최대 60초, 자연스럽게 답변하면 된다는 점이다. 이 상태에서는 추가 안내를 과도하게 표시하지 않는다.

#### 3번 영역

```text
[녹음 시작하기]
```

- 클릭 시 페이지 이동 없이 `RecordingState: ready → recording`으로 변경한다.
- 첫 번째 녹음이면 `attemptNo=1`, 재녹음이면 `attemptNo=2`를 현재 Attempt에 연결한다.

### 상태 2: 녹음 중 (`recording`)

#### 2번 영역

ready 안내 대신 현재 녹음 중임을 명확히 표시한다.

- 음성 파형 또는 녹음 시각화
- 현재 녹음 시간
- 최대 60초

```text
~~~~~~~ 음성 파형 ~~~~~~~

00:32 / 01:00
녹음 중
```

#### 3번 영역

```text
[일시정지]                  [그만하기]
```

- `일시정지`: `recording → paused`, 페이지 유지
- `그만하기`: 녹음을 종료하고 `completed`로 변경
- 60초 도달: 자동으로 녹음을 종료하고 `completed`로 변경
- 5초 미만에 `그만하기`를 누르면 완료 처리하지 않고 `5초 이상 녹음해 주세요.`를 표시한다.

### 상태 3: 일시정지 (`paused`)

#### 2번 영역

```text
녹음이 잠시 멈췄어요.

현재 녹음 시간: 00:32 / 01:00
준비되면 이어서 녹음해 주세요.
```

- 파형은 정지된 상태로 표시한다.
- 일시정지 중에는 녹음 시간이 증가하지 않는다.

#### 3번 영역

```text
[계속 녹음하기]            [그만하기]
```

- `계속 녹음하기`: `paused → recording`, 페이지 유지
- `그만하기`: 녹음을 종료하고 `completed`로 변경

### 상태 4: 녹음 완료 (`completed`)

#### 2번 영역

```text
녹음이 완료됐어요.

총 녹음 시간: 00:42
~~~~~~~ 녹음된 음성 파형 ~~~~~~~
[▶ 녹음 다시 듣기]
```

- 녹음된 Blob을 재생할 수 있어야 한다.
- 5초 이상 60초 이하로 완료된 녹음만 분석 대상으로 인정한다.
- 질문 영역은 계속 동일하게 유지한다.

#### 3번 영역

```text
[다시 녹음]                  [분석하기]
```

- `다시 녹음`: 같은 질문을 유지하고 `completed → ready`로 변경한다. 기존 미분석 녹음은 새 녹음으로 대체한다.
- `분석하기`: 현재 Attempt의 녹음과 메타데이터로 분석 요청을 시작하고 다음 `분석 중` 단계로 이동한다.
- 녹음 데이터가 없거나 5초 미만이면 `분석하기`를 비활성화한다.

### 주요 상태 전환

```text
첫 화면에서 [연습 시작하기]
        ↓ 페이지 이동
녹음 페이지 · ready
        │ [녹음 시작하기]
        ▼
recording ──[일시정지]──> paused
    │                         │
    │ [그만하기]              │ [계속 녹음하기]
    │                         ▼
    └──────────────────── recording
        │
        └──────────────> completed
                         │       │
                    [다시 녹음] [분석하기]
                         │       └──> 분석 중
                         ▼
                       ready
```

### 오류 상태 예시

오류 상태도 같은 녹음 페이지 안에서 처리한다. 선택한 질문, 현재 Attempt, 이미 측정된 녹음 시간은 가능한 경우 유지한다.

#### `recordingStartError` · 녹음 시작 실패

`녹음 시작하기`를 눌렀지만 녹음이 시작되지 않은 상태다.

```text
1. 선택한 질문
"1분 자기소개를 해주세요."

2. 녹음을 시작하지 못했어요.
마이크 연결 상태를 확인한 뒤 다시 시도해 주세요.
문제가 계속되면 마이크 권한을 다시 확인해 주세요.

3. [다시 시도]
```

페이지 이동 없이 현재 녹음 페이지에서 `ready` 상태로 재시도한다.

#### `recordingInterrupted` · 녹음 중 마이크 연결 끊김

마이크 장치가 제거되거나 `MediaStream`이 중단된 상태다.

```text
1. 선택한 질문
"1분 자기소개를 해주세요."

2. 녹음이 중단됐어요.
마이크 연결 상태를 확인해 주세요.

3. [다시 녹음]
```

중단 전 녹음 파일을 사용할 수 있는지는 팀 합의에 따른다. 자동으로 첫 화면이나 질문 선택 상태로 보내지 않는다.

#### `tooShort` · 5초 미만 종료

```text
2. 답변을 조금만 더 들려주세요.
분석하려면 최소 5초 이상 녹음이 필요해요.

3. [다시 녹음]
```

선택한 질문은 유지한다. `그만하기` 자체를 5초 전 차단할지 여부는 기존 합의 항목을 따른다.

## 4단계 오류 상태

#### `recordingFileError` · 녹음 파일 생성 실패

녹음은 끝났지만 Blob/File을 만들지 못한 상태다.

```text
1. 선택한 질문
"1분 자기소개를 해주세요."

2. 녹음 파일을 준비하지 못했어요.
같은 질문으로 다시 녹음해 주세요.

3. [다시 녹음]
```

`분석하기`는 표시하지 않거나 비활성화한다.

#### `playbackError` · 다시 듣기 재생 실패

파일은 존재하지만 오디오 재생에 실패한 상태다.

```text
2. 총 녹음 시간: 00:42
녹음 내용을 재생하지 못했어요.
다시 시도하거나 새로 녹음할 수 있어요.
[다시 듣기]

3. [다시 녹음]                  [분석하기]
```

재생 실패만으로 분석을 자동 차단하지 않는다. 파일 검증이 통과하면 `분석하기`를 유지하되, 최종 허용 여부는 합의 결과를 따른다.

#### `recordingValidationError` · 분석 전 파일 검증 실패

파일이 없거나 손상됐거나 지원하지 않는 형식인 상태다.

```text
2. 녹음 파일을 확인하지 못했어요.
다시 녹음한 뒤 분석을 시작해 주세요.

3. [다시 녹음]
분석하기: 비활성화
```

분석 중 화면으로 이동하지 않고 현재 녹음 완료 상태에 오류를 표시한다.

## 5. 분석 중 화면

### 화면 목적

`분석하기`를 누른 뒤 현재 Attempt를 분석하는 동안 진행 상태만 간결하게 보여준다. 오류도 별도 페이지가 아니라 이 화면의 상태로 처리한다.

### 필요한 UI 요소

- 로딩 spinner 또는 간단한 loading animation
- 메인 문구: `말하기 습관을 확인하고 있어요.`
- 보조 문구: `잠시만 기다려 주세요.`

### 필요한 상태

```text
AnalysisState
- analyzing
- completed
- error
- timeout
- serverConnectionError
```

### 상태별 화면 처리

- `analyzing`: 로딩, 메인 문구, 짧은 보조 문구만 표시한다.
- `completed`: 현재 Attempt가 1차면 `6. 1차 분석 결과`로 이동한다.
- `error`: 분석 결과를 임의로 표시하지 않고 재시도 안내를 보여준다.
- `timeout`: 분석 시간이 길어졌다는 안내와 재시도 선택지를 보여준다.
- `serverConnectionError`: 연결 안내와 다시 시도 버튼을 보여준다.

### 오류 상태 예시

#### `analysisError`

```text
분석을 완료하지 못했어요.
잠시 후 다시 시도해 주세요.

[다시 분석하기]   [다시 녹음]
```

#### `analysisTimeout`

```text
분석에 시간이 조금 더 걸리고 있어요.
다시 시도하거나 같은 질문으로 다시 녹음할 수 있어요.

[다시 분석하기]   [다시 녹음]
```

#### `serverConnectionError`

```text
분석 서버와 연결하지 못했어요.
인터넷 연결을 확인한 뒤 다시 시도해 주세요.

[다시 시도]
```

재시도 시 선택한 질문과 현재 Attempt를 유지한다.

### Figma용 텍스트 와이어프레임

```text
┌────────────────────────────────────────────┐
│                  ◌                         │
│        말하기 습관을 확인하고 있어요.       │
│ 잠시만 기다려 주세요.                       │
└────────────────────────────────────────────┘
```

## 6. 1차 분석 결과 화면

### 화면 목적

1차 답변의 전사문, 전달력 분석, 최대 2개의 행동 피드백을 보여준다. 분석 일부가 실패해도 가능한 결과는 유지하며, TTS 예시를 들은 뒤 같은 질문으로 재녹음할 수 있게 한다.

### 위에서 아래로 보이는 화면 구조

1. 선택한 질문
2. 내 답변(STT 전사문)
3. 분석 결과 + 피드백
4. 피드백 반영 음성 듣기
5. `재녹음 하기`

### 6-1. 선택한 질문

- 상단 라벨: `선택한 질문`
- 선택한 질문 문장을 그대로 표시한다.
- 1차 결과 화면에서도 `activeQuestionId`와 질문 문장을 유지한다.
- 질문을 변경하는 기능은 표시하지 않는다.

### 6-2. 내 답변

```text
내 답변

안녕하세요. 저는 Python을 활용한 데이터 분석 프로젝트를 진행했고
어... 팀원들과 협업하면서...
```

- STT 결과를 그대로 표시한다.
- 사용자의 문장을 임의로 수정하거나 편집하지 않는다.
- 필러가 전사 결과에 포함되어 있으면 그대로 표시할 수 있다.
- 편집 기능은 추가하지 않는다.

### 6-3. 분석 결과와 피드백

데스크톱에서는 `분석 결과`와 `피드백`을 같은 행의 두 카드로 배치한다. 모바일에서는 세로로 쌓는다.

```text
┌──────────────────────┐ ┌──────────────────────┐
│ 분석 결과            │ │ 피드백               │
│ 말하기 속도          │ │ 1. 행동 안내         │
│ 긴 침묵              │ │ 2. 행동 안내         │
│ 반복 표현            │ │                      │
└──────────────────────┘ └──────────────────────┘
```

MVP 분석 항목:

- 말하기 속도
- 긴 침묵
- 반복 표현

확정되지 않은 기준값이나 정상 범위는 임의로 만들지 않는다.

피드백은 최대 2개만 제공하며 평가보다 행동 안내 중심으로 작성한다.

예:

```text
문장 사이에 짧게 쉬어가 보세요.

'음', '어'가 나오는 구간에서는
잠깐 멈췄다가 이어서 말해도 괜찮아요.
```

사용자를 평가하거나 합격 가능성을 암시하는 표현은 사용하지 않는다.

### 6-4. 분석 결과 일부 없음 (`partialAnalysisError`)

STT는 성공했지만 일부 분석값만 계산되지 않은 경우 전체 결과 화면을 실패 처리하지 않는다.

예:

```text
말하기 속도: 정상 출력
긴 침묵: 계산 실패
반복 표현: 정상 출력
```

계산되지 않은 항목에만 다음 안내를 표시한다.

```text
이번 답변에서는 해당 항목을 확인하지 못했어요.
```

나머지 분석 결과와 피드백은 계속 표시한다.

### 6-5. TTS 피드백 반영 음성

분석 결과와 피드백 아래에 `피드백 반영 음성 듣기` 영역을 배치한다.

- 안내 문구: `피드백을 반영한 전달 방식을 음성으로 들어보세요.`
- 제공 기능: 재생, 멈춤
- 다운로드, 배속, 음성 선택, 구간 반복, 세부 볼륨 조절은 제공하지 않는다.

```text
피드백 반영 음성 듣기
피드백을 반영한 전달 방식을 음성으로 들어보세요.

[▶ 재생]
재생 중: [■ 멈춤]
```

### TTS 오류 상태

TTS 오류가 발생해도 분석 결과와 피드백은 유지한다.

#### `ttsGenerationError`

```text
피드백 음성을 준비하지 못했어요.
잠시 후 다시 시도해 주세요.
[다시 시도]
```

#### `ttsPlaybackError`

```text
피드백 음성을 재생하지 못했어요.
[다시 재생]
```

분석 결과·피드백·`재녹음 하기`는 계속 사용할 수 있다.

#### `ttsLoading`

```text
피드백 음성을 준비하고 있어요.
◌ loading
```

TTS 로딩 중에도 분석 결과와 피드백을 먼저 볼 수 있어야 한다.

### STT 오류 상태

#### `sttNoSpeech`

```text
답변 내용을 충분히 인식하지 못했어요.
조금 더 또렷하게 다시 녹음해 주세요.
[다시 녹음]
```

빈 분석 결과 카드나 잘못된 피드백은 표시하지 않는다.

#### `sttPartialError`

```text
일부 음성을 정확히 인식하지 못했어요.
전사 내용을 참고해 주세요. 필요하면 다시 녹음할 수 있어요.
```

인식된 전사문과 분석 가능한 결과만 표시하며, 전사문을 임의로 보정하지 않는다.

### Figma용 텍스트 와이어프레임

```text
┌────────────────────────────────────────────────────┐
│ 선택한 질문                                        │
│ 1분 자기소개를 해주세요.                           │
├────────────────────────────────────────────────────┤
│ 내 답변                                            │
│ 안녕하세요. 저는 ... 어... 프로젝트를...          │
├─────────────────────────┬──────────────────────────┤
│ 분석 결과               │ 피드백                   │
│ 말하기 속도             │ 1. 문장 사이에          │
│ 긴 침묵                 │    잠깐 쉬어보세요.      │
│ 반복 표현               │ 2. 음·어 대신 잠시     │
│                         │    멈춰도 괜찮아요.      │
├─────────────────────────┴──────────────────────────┤
│ 피드백 반영 음성 듣기                              │
│ 피드백을 반영한 전달 방식을 음성으로 들어보세요.  │
│                    [▶ 재생]                        │
├────────────────────────────────────────────────────┤
│                  [재녹음 하기]                     │
└────────────────────────────────────────────────────┘
```

## 7. 재녹음 하기

### 화면 목적

1차 분석 결과 화면에서 다음 연습으로 이어질 수 있도록 `재녹음 하기` CTA만 활성화한다. 실제 2차 녹음 화면의 구조와 상태는 별도 요청에서 정의한다.

### 주요 동작

- 버튼 라벨: `재녹음 하기`
- 1차 분석 결과 화면에서 버튼을 활성화한다.
- 클릭 시 선택한 질문을 유지한 채 다음 재녹음 흐름을 시작하도록 연결한다.
- 질문 선택 화면으로 돌아가는 동작은 정의하지 않는다.
- 실제 이동 화면, 2차 Attempt 생성 시점, 녹음 준비 상태는 후속 문서에서 정의한다.

```text
1차 분석 결과
  ↓ 피드백 확인
  ↓ 피드백 반영 음성 듣기
[재녹음 하기]
  ↓
후속 재녹음 화면 정의 예정
```

### 필요한 상태

```text
RerecordActionState
- enabled
- clicked
```

### Figma용 텍스트 와이어프레임

```text
┌────────────────────────────────────────────┐
│ 1차 분석 결과                               │
│ 선택한 질문: "1분 자기소개를 해주세요."      │
│                                            │
│ [재녹음 하기]                              │
└────────────────────────────────────────────┘
```

## 8. 재녹음 준비 화면

### 화면 목적

1차 분석 결과에서 `재녹음 하기`를 누른 뒤 같은 질문을 다시 확인하고, 필요하면 피드백 음성을 다시 들은 다음 2차 녹음을 시작한다.

### 필요한 UI 요소

- 선택한 질문
- 재녹음 안내
- 보조 영역: 피드백 음성 다시 듣기
- 메인 CTA: `재녹음 시작하기`

### 상태와 동작

- 질문은 변경하지 않는다.
- 질문 선택 화면으로 돌아가지 않는다.
- 피드백 음성은 재녹음 시작 전까지만 재생할 수 있다.
- `재녹음 시작하기` 클릭 시 `Attempt=2`로 2차 녹음을 시작한다.
- 피드백 음성이 재생 중이면 재녹음 시작과 동시에 중지한다.
- 2차 녹음 시작 후에는 피드백 음성 재생을 비활성화한다.

### 안내 문구

```text
이번에는 피드백을 떠올리며 다시 말해볼까요?

완벽하게 바꾸려 하지 않아도 괜찮아요.
한 가지씩 적용해 보세요.
```

### Figma용 텍스트 와이어프레임

```text
┌─────────────────────────────────────────┐
│ 선택한 질문                              │
│ 1분 자기소개를 해주세요.                 │
├─────────────────────────────────────────┤
│ 이번에는 피드백을 떠올리며               │
│ 다시 말해볼까요?                         │
│                                         │
│ 완벽하게 바꾸려 하지 않아도 괜찮아요.    │
│ 한 가지씩 적용해 보세요.                 │
│                                         │
│ 피드백 음성 다시 듣기                    │
│ [▶ 재생]                                 │
├─────────────────────────────────────────┤
│           [재녹음 시작하기]              │
└─────────────────────────────────────────┘
```

피드백 음성은 `재생`과 `멈춤`만 제공하며, 다운로드·배속·음성 선택·구간 이동은 제공하지 않는다.

## 9. 2차 녹음 화면

### 화면 목적

1차 녹음 화면의 UI와 상태 구조를 그대로 재사용해 같은 질문의 2차 답변을 녹음한다. 차이는 `Attempt=2`뿐이다.

### 필요한 상태

```text
PracticeStep
- secondRecording

Attempt
- second

RecordingState
- ready
- recording
- paused
- completed
```

### 상태별 화면

- `ready`: 1차 녹음의 준비 화면 구조를 재사용한다.
- `recording`: 질문 고정, 음성 파형, 녹음 시간, 최대 60초를 표시한다.
  - 안내: `잘 듣고 있어요. 편하게 이어서 말씀해 주세요.`
  - 버튼: `[그만하기] [일시정지]`
- `paused`: 질문과 현재 시간을 유지한다.
  - 안내: `잠시 멈춰 있어요. 준비되면 이어서 말씀해 주세요.`
  - 버튼: `[그만하기] [이어서 녹음하기]`
- `completed`: 1차 녹음 완료 UI를 재사용한다.
  - 안내: `답변 녹음이 완료됐어요.`
  - 보조: `한 번 들어보고 분석을 시작해 볼까요?`
  - 버튼: `[다시 녹음] [분석하기]`

`다시 녹음`을 눌러도 Attempt 3을 만들지 않고 Attempt 2를 유지한 채 2차 녹음을 다시 시작한다.

### 2차 녹음 오류

1차 녹음에서 정의한 오류 UX를 재사용한다.

- 마이크 사용 불가
- 녹음 시작 실패
- 녹음 중 연결 끊김
- 5초 미만
- 녹음 파일 생성 실패
- 다시 듣기 실패

오류가 발생해도 선택한 질문과 `Attempt=2`는 유지한다.

### Figma용 텍스트 와이어프레임

```text
┌─────────────────────────────────────────┐
│ 선택한 질문                              │
├─────────────────────────────────────────┤
│ ~~~~~~~~~ 음성 파형 ~~~~~~~~~            │
│                                         │
│             00:23 / 01:00              │
│ 잘 듣고 있어요.                          │
│ 편하게 이어서 말씀해 주세요.             │
├─────────────────────────────────────────┤
│ [그만하기]       [일시정지]              │
└─────────────────────────────────────────┘
```

## 10. 2차 분석 중 화면

2차 녹음 완료 화면에서 `분석하기`를 누르면 1차 분석 중 화면을 그대로 재사용한다.

- 메인 문구: `말하기 습관을 확인하고 있어요.`
- 보조 문구: `잠시만 기다려 주세요.`
- UI: spinner 또는 간단한 loading animation
- 성공: `2차 분석 결과`로 이동
- 실패·timeout·서버 연결 오류·STT 실패: 1차 분석 중 화면에서 정의한 오류 UX를 재사용한다.

## 11. 2차 분석 결과 화면

### 화면 목적

새로운 피드백이나 새로운 TTS를 제공하지 않고 1차와 2차의 변화 비교에 집중한다.

### 필요한 UI 요소

1. 선택한 질문
2. `2차 답변` STT 전사문
3. `1차 / 2차 결과 비교`
4. `더 좋아진 점 확인하기`
5. `첫 화면으로 돌아가기`

2차 답변은 Attempt 2의 STT 결과를 그대로 표시하며 편집 기능은 제공하지 않는다.

비교 항목은 1차와 동일하게 다음 3개만 사용한다.

- 말하기 속도
- 긴 침묵
- 반복 표현

### 위에서 아래로 보이는 화면 배치

```text
┌──────────────────────────────────────────────────┐
│ 선택한 질문                                      │
│ 1분 자기소개를 해주세요.                         │
├──────────────────────────────────────────────────┤
│ 2차 답변                                         │
│ "안녕하세요. 저는 Python을 활용한..."            │
├──────────────────────────────────────────────────┤
│ 1차 / 2차 결과 비교                              │
│ ┌──────────────────┐ ┌──────────────────┐       │
│ │ 1차 분석 결과    │ │ 2차 분석 결과    │       │
│ │ 말하기 속도      │ │ 말하기 속도      │       │
│ │ 긴 침묵          │ │ 긴 침묵          │       │
│ │ 반복 표현        │ │ 반복 표현        │       │
│ └──────────────────┘ └──────────────────┘       │
├──────────────────────────────────────────────────┤
│        [더 좋아진 점 확인하기 ▼]                 │
├──────────────────────────────────────────────────┤
│             [첫 화면으로 돌아가기]               │
└──────────────────────────────────────────────────┘
```

### 비교 값 표시

1차와 2차는 동일한 계산 기준으로 비교한다. 아래 수치는 와이어프레임 예시일 뿐이다.

```text
말하기 속도: 1차 380 CPM → 2차 350 CPM
긴 침묵: 1차 3회 → 2차 1회
반복 표현: 1차 5회 → 2차 2회
```

수치가 좋아졌다고 단정하지 않는다. 실제 변화 중심으로 표시하고, 변화가 작으면 `말하기 속도는 1차와 비슷했어요.`처럼 표현하거나 수치만 표시한다.

### 상세 변화 펼치기

`ComparisonDetailState`의 기본값은 `collapsed`다.

- 버튼: `[더 좋아진 점 확인하기 ▼]`
- 클릭: `expanded`, 현재 화면 유지
- 펼친 상태: `[더 좋아진 점 확인하기 ▲]`와 변화 내역 표시
- 상세 계산 실패: 기본 비교는 유지하고 펼침 영역에 `상세 변화 내용을 확인하지 못했어요.` 표시

일부 비교값이 없으면 해당 항목에만 `비교할 결과가 없어요.`를 표시한다.

## 12. 첫 화면으로 돌아가기

2차 결과 비교 화면의 마지막에 `[첫 화면으로 돌아가기]`를 둔다.

- 현재 진행 중 UI 상태만 초기화한다.
- 선택 질문, 현재 Attempt 진행 상태, 녹음 Blob/File 참조, AnalysisState, ComparisonDetailState, TTS playback 상태를 초기화한다.
- 완료된 연습 기록은 삭제하지 않는다.
- 첫 화면은 질문 미선택 상태로 돌아가 다른 질문으로 새 연습을 시작할 수 있다.

## 13. 연습 기록

완료된 연습을 목록으로 확인하고, 질문을 선택하면 기존 결과 UI를 조회 전용으로 재사용한다.

### 13-1. 기본 구조

상단에는 `연습 기록` 제목과 오른쪽의 `[전체 삭제]` 버튼을 배치한다. 기록이 없을 때는 전체 삭제 버튼을 표시하지 않거나 비활성화한다.

각 기록에는 다음을 표시한다.

- 연습 질문
- 연습 완료 날짜/시간
- 오른쪽 `[삭제]` 버튼

질문 영역 클릭과 삭제 버튼 클릭은 서로 다른 동작으로 구분한다. 질문을 클릭하면 해당 연습 결과를 조회하고, 삭제 버튼을 클릭하면 삭제 확인 UI를 표시한다.

```text
┌────────────────────────────────────────────┐
│ 연습 기록                         [전체 삭제] │
├────────────────────────────────────────────┤
│ 질문 1분 자기소개를 해주세요.   2026.08.18  삭제 │
│ 질문 지원 동기를 말해주세요.     2026.08.17  삭제 │
├────────────────────────────────────────────┤
│ 연습 기록은 생성 후 최대 24시간 동안 보관돼요. │
└────────────────────────────────────────────┘
```

### 13-2. 기록 목록 상태

```text
SessionResultState:
- loading
- hasResults
- empty
- loadError
```

기록을 불러오는 동안 로딩 상태를 표시한다. 기록 불러오기에 실패하면 다음을 표시한다.

```text
연습 기록을 불러오지 못했어요.
잠시 후 다시 시도해 주세요.

[ 다시 시도 ]
```

`[다시 시도]`를 누르면 기록 목록을 다시 요청한다.

### 13-3. 개별 기록 삭제

각 기록 오른쪽의 `[삭제]`를 누르면 바로 삭제하지 않고 확인 UI를 표시한다.

```text
이 연습 기록을 삭제할까요?

삭제하면 이 연습의 녹음, 전사문, 분석 결과,
피드백과 비교 결과를 다시 확인할 수 없어요.

[ 취소 ] [ 삭제하기 ]
```

- `[취소]`: 확인 UI를 닫고 목록을 유지한다.
- `[삭제하기]`: 해당 세션의 삭제를 요청한다.
- 삭제 성공 여부를 확인한 뒤에 해당 기록만 목록에서 제거한다.
- 다른 기록이 남아 있으면 나머지 목록을 그대로 표시한다.

개별 삭제 실패 시 다음을 표시한다.

```text
연습 기록을 삭제하지 못했어요.
잠시 후 다시 시도해 주세요.

[ 다시 시도 ]
```

실제 삭제 성공 여부가 확인되지 않으면 목록에서 기록을 제거하지 않는다. `[다시 시도]`는 해당 기록의 삭제 요청을 다시 실행한다.

### 13-4. 전체 삭제

기록이 하나라도 있을 때 상단의 `[전체 삭제]`를 사용할 수 있다. 버튼을 누르면 바로 삭제하지 않고 확인 UI를 표시한다.

```text
모든 연습 기록을 삭제할까요?

저장된 모든 연습 기록과 관련 데이터가 삭제되며
다시 확인할 수 없어요.

[ 취소 ] [ 전체 삭제하기 ]
```

- `[취소]`: 확인 UI를 닫고 기존 목록을 유지한다.
- `[전체 삭제하기]`: 현재 사용자의 저장된 모든 연습 세션 삭제를 요청한다.
- 전체 삭제 성공 여부를 확인한 뒤에만 목록을 빈 상태로 변경한다.

전체 삭제 실패 시 다음을 표시한다.

```text
일부 기록을 삭제하지 못했어요.
잠시 후 다시 시도해 주세요.
```

삭제 성공 여부가 확인되지 않으면 기록을 모두 사라진 것처럼 표시하지 않는다. 실패 시 현재 확인 가능한 목록을 유지하고 다시 시도할 수 있어야 한다.

### 13-5. 삭제 범위

삭제 범위는 기존 SDD 정책을 그대로 따른다. 새로운 삭제 정책을 추가하지 않는다.

개별 삭제는 해당 세션에 연결된 다음 데이터를 삭제한다.

- 원본 녹음
- TTS 음성
- STT 전사문
- 분석 결과
- 피드백
- 비교 결과
- 세션 기록

전체 삭제는 현재 사용자의 저장된 모든 연습 세션에 대해 위 데이터를 삭제한다.

기존 SDD 정책에 따라 연습 기록은 생성 후 최대 24시간 동안 보관한다. Storage는 비공개 버킷을 사용하며, 사용자 음성·전사문은 추가 학습, Voice Cloning, 공개 저장소에 사용하지 않는다. 장기 추세 분석은 제공하지 않는다.

### 13-6. 빈 상태

기록이 없거나 전체 삭제가 성공하면 다음 빈 상태를 표시한다.

```text
아직 연습 기록이 없어요.
새로운 질문으로 연습을 시작해 보세요.

[ 연습하러 가기 ]
```

`[연습하러 가기]`를 누르면 첫 화면의 질문 선택 상태로 이동한다.

### 13-7. 기록 결과 조회

질문 영역을 클릭하면 새로운 복잡한 상세 화면을 만들지 않고 기존 결과 UI를 조회 전용으로 재사용한다.

조회 내용:

- 질문
- 1차 답변
- 1차 분석 결과
- 1차 피드백
- 2차 답변
- 1차 / 2차 비교 결과
- 더 좋아진 점

조회 화면에서는 `재녹음 하기`와 같은 진행용 CTA를 표시하지 않는다. 마지막에는 `[연습 기록으로 돌아가기]`만 제공한다.

### 13-8. 연습 기록 MVP 범위

다음 기능만 제공한다.

1. 기록 목록
2. 질문 클릭 → 결과 조회
3. 개별 삭제
4. 전체 삭제
5. 빈 상태

다음 기능은 추가하지 않는다.

- 검색
- 필터
- 정렬 설정
- 즐겨찾기
- 장기 통계
- 장기 추세 분석
- 페이지네이션

목록 하단에는 다음 안내를 작게 표시한다.

`연습 기록은 생성 후 최대 24시간 동안 보관돼요.`

   │ 분석하기

   │ 분석 완료
