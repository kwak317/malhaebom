# Target State

> 제공 기획 기반 운영 문서. 기능·기술·정책은 목표 또는 재사용 계획이며 현재 구현 완료를 뜻하지 않는다. 기존 1차 코드는 이관되었으며 정적 조사 결과는 [CURRENT_STATE](CURRENT_STATE.md)를 따른다. 실행 검증은 별도다.

## 목표

공고 탐색·추천, 원문 수집·요구사항 분석, 기업 정보 조사, 공고 공급자와 직무·질문 유형 확장을 제품 범위에서 일괄 제외하지 않는다. 현재 구현과 검증 완료 여부는 `CURRENT_STATE.md` 및 기능별 증거로 구분한다.

기존 말해봄의 음성 연습 자산을 재사용하면서, 선택한 신입 백엔드 채용공고의 요구사항과 사용자의 프로젝트 문제 해결 답변을 연결하는 구조화 코칭 흐름을 구현한다.

2026-09-28 요청으로 기존 기본 질문 1~10번에도 질문별 활성 기준을 연결한다. 자기소개·지원동기·협업·성장 계획 등에 문제 해결 전용 기준을 강제하지 않는다. 새로운 규칙은 팀 초안이며 추가 질문의 품질 측정은 별도다 ([Spec](specs/all-preset-question-coaching.md)).

## Must Have

### 공고·직무 맥락
- [ ] 검토된 신입 백엔드 공고 목록 제공
- [ ] 세션에서 공고 1개와 요구사항 1~2개 고정
- [ ] 공고 스냅샷·출처·기준 시점·요구사항 ID 저장
- [ ] 필요 시 관련 직무/NCS 정의를 제한적으로 연결
- [ ] 공고에 없는 조건을 직무 정의에서 가져와 기업 요구사항처럼 표시하지 않음

### 답변 버전과 근거
- [ ] STT 원문과 사용자 확인 텍스트를 분리
- [ ] 확인된 답변을 revision으로 고정
- [ ] 서버가 문장 ID를 계산
- [ ] 코칭·인용·비교가 동일 revision을 참조
- [ ] 수정 중 생성된 오래된 결과를 최신 결과로 표시하지 않음

### 내용 코칭
- [ ] C/R/A/D/V 중 질문별 활성 기준만 평가
- [ ] `met / partial / not_observed / undetermined` 상태 사용
- [ ] `met`, `partial`은 현재 답변의 실제 인용을 요구
- [ ] 공고 관련성은 요구사항별로 별도 판정
- [ ] 부족 시 확인 질문 최대 1개
- [ ] 내용·전달력 다음 행동 합계 최대 2개
- [ ] 없는 수치·성과·역할을 생성하지 않음

### 확인 응답
- [ ] 확인 질문 응답을 원래 답변과 별도 저장
- [ ] `수행했지만 생략 / 수행하지 않음 / 기억·판단 불확실` 상태 구분
- [ ] 확인 응답으로 1차 답변 판정을 소급 변경하지 않음
- [ ] 사용자의 진술을 사실 인증 완료로 표시하지 않음

### 재답변 비교
- [ ] 동일 공고·질문·Skill·생성 설정 조건 확인
- [ ] 같은 `criterion_id` 상태 변화를 서버가 계산
- [ ] 양쪽 답변의 근거를 함께 표시
- [ ] `undetermined` 포함 시 단순 개선/퇴보 순위화 금지
- [ ] 설명 보완을 실제 역량 향상으로 표현하지 않음

### MCP
- [ ] `get_question`
- [ ] `get_job_context`
- [ ] `get_job_competency`
- [ ] `get_practice_attempt`
- [ ] `compare_attempts`
- [ ] 소유자·만료·허용 범위 검사
- [ ] 연구용 정답/원문은 운영 MCP에 노출하지 않음

### LLM/검증
- [ ] 한 서비스 계층에서 피드백 모델 호출
- [ ] 구조화 출력
- [ ] Pydantic 형식 검증
- [ ] 인용·기준 ID·행동 대상·중복/누락 검증
- [ ] 제한된 재시도
- [ ] 최종 실패 시 `unavailable`

### 공식 제출 조건 연결

공통 완료 조건과 검증 증거는 [REQUIREMENTS](REQUIREMENTS.md)를 따른다. 아래는 팀 목표이며 공식 조건을 대체하지 않는다. 배포 URL·소개 페이지·10분 재현·endpoint·제출 마감도 함께 확인한다.

### 관측·평가
- [ ] Langfuse trace
- [ ] Prompt/Skill 버전 연결 및 배포 없이 Prompt 교체·rollback 시연
- [ ] 모델 2개 이상 비교
- [ ] 30건 품질 평가, 독립 판정 근거와 Langfuse Dataset 등록·동일 셋 재측정
- [ ] 고유 입력 100건 계약 평가 및 100건 이상 실행 준수율 실측
- [ ] 일반 피드백 기준선과 동일 조건 비교
- [ ] 실제 MCP/권한/저장 통합 검증

## 완료 상태 표기

각 항목은 아래 중 하나로 관리한다.

- `NOT_STARTED`
- `IN_PROGRESS`
- `DONE`
- `BLOCKED`
- `DEFERRED`

## 비교 후 대화의 운영 경계

해당 세션의 텍스트 면접 대화를 이어갈 수 있다. 현재 구현은 단일 worker 임시 메모리이며 새로고침·재시작 뒤 장기 복원과 다중 worker 공유는 이번 범위에 포함하지 않는다.
