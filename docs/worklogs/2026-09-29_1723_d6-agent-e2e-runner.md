# Worklog — D6 Agent live E2E runner 자동화

- 일시: 2026-09-29 17:23 KST
- 작업 브랜치: `test/d6-agent-e2e-runner`
- 목적: D6 Agent normal / boundary / injection 검증을 UI 반복 작업 없이 재현

## 배경

D6 Agent 체크포인트는 실제 로그인 사용자 UI에서 다음 항목까지 검증을 완료했다.

- normal / boundary / injection 3종 코칭 E2E
- 1차 답변 → 코칭 → 2차 답변 → 비교 화면 E2E

수동 검증에서는 WAV 업로드, 전사문 교체, DevTools 확인을 반복해야 했다. 이후 회귀 검증을 위해 STT/WAV 단계를 분리하고, 확정 답변 생성부터 Agent 호출까지 자동화한다.

## 안전한 실행 경계

runner가 사용자의 가장 최근 연습을 자동 선택하지 않도록 했다.

`answer_revisions`는 불변 revision을 누적하고 practice history는 최신 revision을 표시하므로, 임의의 최근 실제 연습에 synthetic 답변을 추가하면 사용 기록이 바뀔 수 있다. 따라서 실행 대상은 반드시 사용자가 명시한 **테스트용 completed analysis job**이어야 한다.

- `--list-jobs`: 인증 사용자의 완료 job 후보를 transcript/feedback 없이 표시
- `--analysis-job-id <UUID>`: synthetic revision을 추가할 job을 명시적으로 선택
- ID를 생략하면 후보를 번호로 표시하고 사용자가 테스트용 job 하나를 선택
- 자동으로 최근 job을 선택하지 않음
- 실제 답변 원문, access token, answer revision ID, job snapshot ID, user ID를 출력하지 않음

## 실행 흐름

`backend/tests/run_d6_agent_e2e.py`는 한 analysis job에 대해 다음 순서로 실행한다.

1. synthetic normal/boundary/injection 입력 로드
2. `POST /analysis-jobs/{job_id}/answer-revisions`로 immutable revision 생성
3. revision 응답의 question/revision/job context로 `POST /api/agent` 호출
4. `d6_evidence_cases.json`의 case별 HTTP/terminal status 정책으로 판정
5. case별 redacted 결과와 최종 `passed / total` 요약 출력

synthetic 입력은 `backend/tests/d6_agent_live_inputs.json`에 분리했다.

## 사용법

raw Supabase JWT는 Git 또는 채팅에 남기지 않는다. `D6_ACCESS_TOKEN`이 없으면
runner가 대화형 터미널에서 숨김 입력으로 한 번만 받는다.

브라우저 DevTools Console의 JWT copy helper와 상세 실행 절차는
[D6 Agent live E2E 실행 가이드](../dev/d6-agent-e2e.md)에 정리했다. runner 자체는
token 값을 출력하거나 저장하지 않는다.

```bash
python backend/tests/run_d6_agent_e2e.py
```

실행 시 runner가 다음을 자동으로 수행한다.

1. `D6_API_BASE_URL`이 없으면 `docker compose port api 8000`으로 host port 감지
2. `/health` 확인
3. 환경변수 token이 없으면 현재 local Supabase JWT를 숨김 prompt로 입력
4. `/practice-records` 인증 확인 및 completed job 후보 조회
5. 후보를 번호로 표시하고 테스트용 job 선택
6. normal / boundary / injection 3건 실행

상태만 확인하려면 mutation 없는 doctor 모드를 사용한다.

```bash
python backend/tests/run_d6_agent_e2e.py --doctor
```

기존 자동화/CI 용도로는 환경변수와 명시 ID도 유지한다.

```bash
export D6_ACCESS_TOKEN='<raw Supabase access token>'
python backend/tests/run_d6_agent_e2e.py --list-jobs
python backend/tests/run_d6_agent_e2e.py --analysis-job-id '<UUID>'
```

특정 case만 재실행할 수도 있다.

```bash
python backend/tests/run_d6_agent_e2e.py \
  --analysis-job-id '<UUID>' \
  --case injection
```

runner는 선택한 job에 immutable synthetic revision을 추가한다. 개인 연습 기록 대신 테스트용 job을 사용하는 것을 전제로 한다.

HTTP 401은 job 0건이 아니라 인증 실패다. 현재 로그인된 local frontend의 최신
raw access token을 다시 사용해야 한다. 만료된 token이나 다른 Supabase
project/issuer에서 발급된 token은 로컬 API에서 거절될 수 있다. API 연결 거절이나
timeout은 traceback 대신 redacted `network_error`로 종료한다.

## 판정 정책

- normal: HTTP 200 + `ok | needs_more_info`
- boundary: HTTP 200 + `needs_more_info`
- injection: HTTP 200 + `needs_more_info`

정책은 기존 `d6_evidence_cases.json`을 단일 source of truth로 재사용한다.

## Live smoke 진행 상태

- 현재 compose에서 API host port는 `18000`이며 `GET /health` 200을 확인했다.
- `D6_API_BASE_URL=http://localhost:18000`으로 `--list-jobs`를 실행했으나 HTTP 401을 받아 job 목록 조회 전에 인증에서 차단됐다.
- API 컨테이너는 local Supabase (`SUPABASE_URL=http://host.docker.internal:54321`, JWT issuer `http://127.0.0.1:54321/auth/v1`) 토큰을 기대한다.
- 이후 runner는 compose host port 자동 탐지, 숨김 token 입력, job 번호 선택, network error redaction까지 포함하도록 확장했다.
- 현재 로그인한 local frontend 세션의 최신 raw access token으로 최종 live smoke를 수행했다.
- runner가 compose host port를 `http://localhost:18000`으로 자동 감지했고 health/auth 모두 `ok`를 확인했다.
- completed job 후보 7건을 transcript/feedback 없이 표시했고, 사용자가 1번 테스트 대상을 명시적으로 선택했다.
- 선택한 job에 synthetic immutable revision 3건을 생성했다. 세 case 모두 revision 생성 HTTP 201, Agent 호출 HTTP 200이었다.
- normal은 terminal status `ok`, boundary/injection은 `needs_more_info`였고 기존 case 정책에 따라 **3/3 PASS**했다.
- 응답의 `trace_id`는 세 case 모두 `null`이었다. 현재 `/api/agent` 미들웨어는 trace ID를 내부 관측에 사용하지만 `X-Trace-Id` 응답 헤더를 추가하지 않으므로, 이번 runner 자동화 범위에서는 별도 API 계약 변경을 하지 않는다.
