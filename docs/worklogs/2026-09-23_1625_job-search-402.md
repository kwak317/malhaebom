# Worklog — 공고 검색 402 진단

- 일시: 2026-09-23 16:25 KST
- 작업자/에이전트: Codex
- 관련 이슈/PR: 없음
- 관련 Spec: [백엔드 공고 후보 추천](../specs/saramin-backend-recommendations.md)

## 1. 목적

README 분석 성공 뒤 공고 검색이 503을 반환한 이유가 출력 토큰 한도인지 확인하고, 코드에서 해결할 수 있는 부분을 반영한다.

## 2. 원인 확인

- 로컬 Compose API는 healthy였고 채팅의 공고 검색 요청 두 번 모두 503이었다. 각 요청에서 두 사이트 웹검색이 OpenRouter 402를 반환했다.
- 동일 키로 출력 한도 없는 웹검색을 직접 호출했을 때 OpenRouter는 최대 65,536토큰을 요청한 것으로 계산했고 당시 가능한 한도를 약 3,639토큰으로 알렸다.
- 이후 OpenRouter가 `Insufficient credits. This account never purchased credits`를 반환했다. 키의 설정된 사용 한도와 계정의 실제 사용 가능 크레딧은 구분된다.

## 3. 수행 내용

- 검색 요청에 출처별 `max_tokens=1536`을 추가하고 짧은 인용 응답을 요청한다.
- 402를 별도로 구분해 계정 크레딧·키 사용 한도 안내를 표시한다. 한 출처만 실패하고 다른 출처의 인용이 있으면 결과를 계속 검증한다.
- 관련 테스트와 명세, 현재 상태, 아키텍처 기록을 갱신했다.

## 4. 검증

- 관련 백엔드 테스트 16개와 전체 격리 백엔드 테스트 278개 통과. 402 안내가 API 응답의 `detail`로 전달되는 것도 검증했다.
- 한도 적용 후 실제 두 출처 검색에서 402 없이 응답했지만 인용은 0건이었다. 뒤이은 검색은 계정 크레딧 부족 402를 반환했다. 실제 검증 공고를 반환하는 경로는 현 키로 입증하지 못했다.
- 최종 API 이미지를 재빌드해 로컬 Compose에 적용했다.

## 5. 제한

- 계정에 사용 가능한 OpenRouter 크레딧이 없어 코드만으로 검색 성공을 보장할 수 없다. 크레딧을 확보한 뒤 검색 인용과 실제 공고 카드 결과를 다시 확인해야 한다.
