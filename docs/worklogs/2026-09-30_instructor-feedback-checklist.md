# 2026-09-30 — 3조 강사 피드백 보완 체크 추가

## 목적

중간 강사 판정에서 3조에 남은 문제 해결력, LLM 제어력, 서비스 완성도, 관찰·평가 지적을 공식 D2~D12 일정과 섞지 않고 별도 체크리스트로 추적한다.

## 작업 전 상태

- 공식 체크포인트 문서는 D2~D12 일정 중심으로 정리되어 있었다.
- 강사 피드백 중 Prompt/Skill 분리는 이후 구현으로 상당 부분 해소됐지만 체크포인트 문서에서 그 근거를 한눈에 확인하기 어려웠다.
- 공고 원문 분석은 실제 구현이 존재하는 반면 일부 제품 문서가 아직 “가까운 미래” 범위로 설명해 현재 구현과 문서 사이에 불일치가 있다.
- backend/frontend 테스트는 반복 실행 기록이 있으나 제품 테스트를 PR마다 자동 실행하는 CI는 별도 추적 항목이 없었다.
- 모델·Prompt 비교 기록은 존재하지만 동일 평가셋의 개선 전후를 최종 artifact로 묶는 작업은 이후 공식 D11~D12와 함께 추적할 필요가 있다.

## 수행한 작업

- `docs/project2-checkpoint-work-cards.md`에 `3조 강사 피드백 보완 체크` 섹션을 추가했다.
- 문제 해결력은 공고 원문 분석의 구현 존재와 문서 범위 불일치를 분리해 부분 완료로 기록했다.
- LLM 제어력은 Prompt와 Skill 책임 분리 구현·테스트를 근거로 완료 상태를 기록했다.
- 서비스 완성도에는 backend/frontend/build를 PR에서 자동 확인하는 제품 테스트 CI를 추가 과제로 기록했다.
- 관찰·평가에는 동일 Dataset/version 기준 before/after 결과와 재현 가능한 artifact 보존을 추가 과제로 기록했다.
- 공식 D10 배포 및 D11~D12 평가 항목과 중복되지 않도록 강사 피드백의 보완 관점만 별도 추적한다.

## 주요 판단과 이유

- 강사 피드백은 공식 Checkpoint 일정 자체가 아니므로 D2~D12의 완료 판정을 변경하지 않는다.
- 공고 원문 분석은 이제 실제 코드 경로가 존재하므로 “범위 밖”이라는 과거 설명을 그대로 유지하는 것보다 문서와 구현을 맞추는 작업이 필요하다.
- 런타임에서 Prompt와 Skill을 합성하는 것 자체는 문제로 보지 않고, 모델 운영 지시와 도메인 규칙의 소스가 분리되어 독립적으로 검토·버전 관리되는지를 완료 기준으로 둔다.
- 로컬 테스트 실행 기록과 CI는 다른 증거이므로 제품 테스트 CI는 별도 미완료 항목으로 둔다.

문서 변경만 수행한다. 코드 경로나 런타임 동작은 변경하지 않는다.

## 발견한 문제

- 공고 원문 분석의 실제 구현 상태와 일부 제품 문서의 미래 범위 설명이 일치하지 않는다.
- GitHub Actions에는 PR 정책/secret 검사와 별개로 제품 backend/frontend 회귀 테스트를 자동 실행하는 항목을 추가 검토해야 한다.

## 미확인 사항

- 강사 피드백 당시 화면의 각 지적이 이후 어느 PR에서 해소되었는지 최종 대응표는 아직 작성하지 않았다.
- before/after 평가 artifact의 최종 저장 형식은 D7 baseline 확정 및 D11~D12 평가 흐름과 함께 정한다.
