# 채팅 자연어 공고 검색 및 다중 출처 연동 작업 기록

## 목표

사용자가 말해봄 채팅에서 `백엔드 관련 공고를 보여줘`처럼 자연어로 요청하면,
서버 LLM이 검색 의도와 검색어를 구조화해 ALIO와 인사혁신처 공공취업정보를 함께
조회하고, 선택한 공고의 원문 근거만 요구사항 및 코칭 문맥에 저장한다.

## 구현

- `POST /api/job-search-intent`를 추가했다. 로그인한 사용자의 채팅 문장을 서버에서
  `google/gemini-3.5-flash-lite` JSON 응답으로 분류해 `should_search`와 `query`를 반환한다.
- 모델 호출이나 응답 형식이 일시적으로 실패해도 공고 요청은 중단되지 않도록, 제한된
  직무 키워드 기반 보조 경로를 서버에만 두었다. 프런트엔드의 기존 키워드 판별은 제거했다.
- 채팅 검색은 LLM이 반환한 검색어로 ALIO와 인사혁신처 공공취업정보를 병렬 조회하고,
  출처별 결과를 각각 보여준다. 한 출처가 실패해도 다른 출처 결과는 유지한다.
- 공고 분석은 제공자가 준 공고 원문을 서버에서 다시 받아 LLM 요구사항 분석에 전달하고,
  요구사항 1~2개를 사용자가 선택한 뒤 기존 연습·코칭 흐름으로 이어진다.
- 실행 포트를 `.env`에서 `WEB_PORT=18080`으로 통일했다.

## 검증

- `npm test -- --run src/api/practiceSetup.test.ts src/pages/PracticeSetupFlow.test.tsx`
  - 2개 파일, 17개 테스트 통과
- `npm run build`
  - TypeScript 검사와 Vite 프로덕션 빌드 통과
- API 컨테이너 단위 테스트
  - `test_job_search_intent.py`: 5개 통과
  - `test_public_employment_recruitment.py`: 4개 통과
  - `test_practice_setup.py`: 10개 통과
  - `test_alio_recruitment.py`: 6개 통과
- 실행 중인 API에서 실제 모델에 `백엔드 관련 공고를 보여줘`를 전달해
  `{"should_search": true, "query": "백엔드"}` 응답을 확인했다.
- `http://localhost:18080/practice`가 200으로 응답하고, 브라우저에서 채팅 입력 화면이
  정상 렌더링되는 것을 확인했다.

## 남은 운영 유의사항

- 브라우저 전체 흐름은 로그인한 계정과 실제 공고·LLM 제공자 응답에 의존한다. 자동화에서는
  인증 토큰을 사용하지 않았으며, UI/계약 테스트와 실제 단건 모델 의도 분류로 대체 검증했다.
- 인사혁신처 제공자의 `Kwrd` 필터 동작이 일관되지 않아 현재 서버는 최신 100건을 받은 뒤
  제목·기관·분류 필드에서 검색어를 필터링한다. 검색 범위 확장이 필요하면 공식 API의
  안정적인 조건 파라미터를 추가 검증해야 한다.
