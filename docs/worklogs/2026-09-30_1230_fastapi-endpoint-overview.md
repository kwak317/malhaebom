# Worklog — FastAPI 전체 기능 표

- 일시: 2026-09-30 12:30 KST
- 작업자/에이전트: Codex
- 관련 이슈/PR: 없음
- 관련 요구사항/결정: 강사 질문에 대응해 세로 슬라이스 대표 경로와 전체 FastAPI 경로를 구분

## 1. 목적

상위 구현 현황 문서가 `POST /api/agent`와 `GET /practice-records`만 제공하는 것처럼 보이지 않도록, 스크린샷 형식의 기능별 API 표를 추가한다.

## 2. 작업 전 상태

- 붙여준 과거 문서는 mock 시점의 두 대표 경로를 자세히 설명한다.
- 현재 `backend/app/main.py`의 라우트 데코레이터 정적 확인 결과, OpenAPI에 노출되는 메서드·경로 조합은 32개, URL 경로는 29개다. 별도 `/health`를 포함하면 33개다.
- 로컬 Docker daemon 연결 실패로 현재 실행 중 API 응답은 재검증할 수 없었다.

## 3. 수행 내용

- 상위 `말해봄_개발기반_구현현황_NCS포함_20260929.md`의 1절 끝에 코칭·음성·공고/NCS/README·분석·기록의 다섯 묶음 표를 추가했다.
- 코드 정의 수와 실행 상태를 구분하고, 자동 생성 `/docs`·`/openapi.json`, MCP 도구, `/health`의 집계 경계를 밝혔다.
- 기존 두 경로의 JSON 예시는 유지하고, Compose 상태 표가 당시 기록임을 명확히 했다.

## 주요 판단과 이유

스크린샷의 `api`·`mcp`·`db`·`worker`를 실제 Compose 서비스처럼 옮기면 현재 두 서비스(`api`, `frontend`) 구성과 충돌한다. 따라서 같은 3열 표 형식으로 FastAPI 기능을 묶고 상태에는 확인 가능한 정적 경로 수를 적었다.

## 6. 발견한 문제 / 남은 리스크

- 현재 Docker daemon에 연결되지 않아 `/openapi.json` 실응답과 개별 엔드포인트의 동작 상태는 재검증하지 않았다.

## 미확인 사항

- 외부 API 키가 필요한 선택형 경로까지 모두 실호출했다는 뜻은 아니다.
