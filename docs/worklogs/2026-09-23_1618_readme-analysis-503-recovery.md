# Worklog — README 분석 503 복구

- 일시: 2026-09-23 16:18 KST
- 작업자/에이전트: Codex
- 관련 이슈/PR: 없음
- 관련 Spec: [GitHub README 분석](../specs/github-readme-gemini-analysis.md)

## 1. 목적

새 OpenRouter 키로 재기동한 뒤 나타난 GitHub README 읽기 실패와 Gemini 분석 503을 진단하고, 지정된 README 분석을 다시 성공시킨다.

## 2. 작업 전 상태와 원인

- `.env`에서 해석된 키와 실행 중인 API 컨테이너 키가 일치했다. GitHub README 단독 조회와 짧은 Gemini 호출은 성공했다.
- 동일 키로 구조화 출력 요청을 보내면 OpenRouter가 402를 반환했다. 출력 상한이 없어 최대 65,536토큰의 비용을 예약하려 했고, 당시 키는 최대 5,966토큰 비용만 허용했다. 기존 코드가 402를 일반 연결 오류로 표시했다.
- 출력 상한을 넣은 뒤 Gemini의 일부 `source_excerpt`가 README의 `**` 강조 표시를 제외한 렌더링 문장을 사용해 원문 대조에서 실패했다. 배지의 텍스트를 합친 인용도 한 건 있었다.

## 3. 수행 내용

- README 분석용 OpenRouter 요청에만 `max_tokens=3072`를 추가하고 402는 크레딧·키 사용 한도 안내로 구분했다. 기존 코칭 요청의 출력 상한은 변경하지 않았다.
- GitHub README 조회의 일시적 연결 실패와 5xx에 한 번 재시도를 추가했다.
- Markdown 강조·백틱을 제외한 연속 문구를 검증 대상으로 삼고, 재요청 후에도 원문에 없는 항목은 제외한다. 검증된 기술과 흐름이 각 하나 이상 없으면 실패를 유지한다. 공고 추천의 README 근거 재검증도 같은 규칙을 사용한다.
- 관련 명세, 현재 상태, 아키텍처 기록을 갱신했다.

## 4. 검증

- 관련 백엔드 테스트 33개와 전체 격리 백엔드 테스트 275개 통과.
- API 컨테이너를 재빌드했다. 지정된 공개 GitHub README를 현재 키로 실제 Gemini 분석해 기술 8개와 프로젝트 흐름 4개를 반환했다.
- 짧은 모델 요청 200과 실제 README 분석 성공은 확인했다. 로그인 브라우저의 `다시 분석` 동작은 직접 다시 조작하지 않았다.

## 5. 제한

- 크레딧이 실제로 소진되거나 모델 제공자가 다시 실패하면 오류가 날 수 있다. 이때 사용자는 구분된 한도 안내 또는 재시도 메시지를 받는다.
