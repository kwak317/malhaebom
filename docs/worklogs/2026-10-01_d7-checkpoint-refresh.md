### 3.2 D7 baseline 수치 확인

`baseline 1차 측정` 문서 상단 비교표의 최신 실행 수치를 D7 baseline 근거로 기록했다.

| 항목 | 첫 실행 | 최신 실행 |
| --- | ---: | ---: |
| 최종 JSON 계약 통과 | 30/30 | 30/30 |
| 자동 전체 통과 | 19/30 | 23/30 |
| 정상 | 11/12 | 12/12 |
| 경계 | 3/10 | 5/10 |
| 실패 유도 | 5/8 | 6/8 |
| p95 지연 | 4.83초 | 5.54초 |
| 30건 비용 | $0.1747 | $0.2151 |

비교 한계도 함께 확인했다.

- 첫 실행은 Gemini 3.5 Flash Lite, strict JSON Schema, 영문 Prompt v1, 단일 호출이다.
- 최신 실행은 같은 모델/출력 형식이지만 사실 추출 후 최종 판정하는 2회 호출 구조다.
- 따라서 Prompt 문구만 바꾼 순수 A/B 비교가 아니다.
- 두 결과는 합성 평가셋의 단일 실행이며 실제 로그인 사용자 품질을 뜻하지 않는다.

같은 Notion 페이지 후반에는 별도의 **9/30 strict JSON Schema 재실행** 수치가 존재한다.

- 출력 계약 30/30
- 자동 전체 20/30
- 정상 10/12
- 경계 3/10
- 실패 유도 7/8

이 수치는 상단 `첫 실행 vs 최신 실행` 비교표의 23/30과 다른 실행이므로 동일 baseline 수치로 섞지 않는다.

### 3.4 출력 파싱/출처/에러 로깅 근거 확인

두 번째 Notion 문서에서 다음을 확인했다.

- JSON/출력 계약 실패 시 최대 1회 보정하고, 보정 후에도 실패하면 `COACHING_OUTPUT_SCHEMA_VIOLATION`으로 종료한다.
- timeout·429·5xx는 출력 보정과 별도의 전송 재시도 정책을 가진다.
- 고정 규칙은 `system`, 질문·답변·공고·보정 요청 등 분석 자료는 `user` 데이터로 분리한다.
- 실패 로그는 `trace_id`, `stage`, `error_code`, `attempt_count`를 기록한다.
- 이 문서 작성 시 실제 provider 실패를 새로 유도한 것은 아니라고 명시되어 있다.

이 내용은 D7의 도메인 지식/사용 위치 재확인과 현재 구조 설명의 보조 근거로 사용하며, 독립적인 운영 E2E 검증으로 과장하지 않는다.

- D7 baseline은 Notion 상단 비교표의 최신 실행 **23/30**을 체크포인트에 사용한다. 같은 페이지 후반의 20/30은 별도 실행이므로 구분한다.
- 저장소에는 개인 복제본 URL이 아니라 사용자가 제공한 원본 workspace URL과 Page ID를 canonical 외부 근거로 기록한다.
- 원본 workspace는 현재 접근 권한이 없어 직접 열람하지 못했으며, 2026-10-01의 내용 확인은 사용자 제공 복제본을 기준으로 했다.
- D7의 `중간 점검 1장`은 내용 통합은 되어 있으나 발표용 단일 장표로 압축된 증거는 확인하지 못했으므로 `[-]`를 유지한다.
- 문서 간 충돌은 존재를 확인했지만 실제 정리 완료 증거는 없으므로 `[-]`를 유지한다.

## 6. 발견한 문제 / 남은 리스크

- `baseline 1차 측정` 한 페이지 안에 23/30과 20/30이라는 서로 다른 실행 수치가 함께 있어, 실행 맥락을 생략하면 혼동할 수 있다.
- Notion 원본은 외부 문서이므로 향후 내용이 수정될 수 있다. 이 Worklog는 2026-10-01에 개인 복제본으로 확인한 시점의 범위와 수치를 기록한다.
- 원본 workspace는 현재 접근 권한이 없어 원본과 복제본의 이후 변경 여부를 직접 비교하지 못했다.
- D7 발표용 중간 점검 1장 압축은 아직 완료 증거가 없다.
- 오래된 계획/체크포인트 문서의 설명 충돌은 실제 정리가 남아 있다.
