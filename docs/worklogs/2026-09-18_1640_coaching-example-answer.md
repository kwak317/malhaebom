## 1. 목적

확정 답변과 검증된 코칭을 바탕으로 대필 위험을 제한한 예시 답변 1개를 결과 화면에 제공한다.

## 2. 작업 전 상태

`/api/agent` 응답과 `CoachingResultPanel`에는 예시 필드·영역이 없었고, 실행 중인 `3000` 프런트와 `8003` API도 구형 계약을 사용했다.

## 3. 수행 내용

- `example_answer`의 상태별 계약·500자 제한·신규 숫자 검증을 추가했다.
- Skill에 현재 답변만 재배열하고 없는 정보는 자리표시자로 남기는 규칙을 추가했다.
- 프런트 카드·사실 확인 안내·코칭 재요청 버튼을 추가했다.
- Prompt·Skill 기본 버전을 각각 v2로 올리고 Mock 평가 입력을 계약에 맞췄다.
- 활성 `8003` 컨테이너와 Docker 이미지를 갱신했다.

## 주요 판단과 이유

legacy 전체 답안 생성은 재활성화하지 않았다. 예시는 판정 근거가 아니며 기존 평가셋의 품질 정답도 소급 생성하지 않았다.

## 4. 변경 파일

백엔드 계약·서비스·테스트, 프런트 API·패널·스타일, `skills/`, `evals/`, 관련 Spec·기준 문서를 변경했다.
