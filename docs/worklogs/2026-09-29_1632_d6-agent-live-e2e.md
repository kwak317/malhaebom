## normal terminal status 판단

프로젝트 제안 문서에는 정상 입력이 반드시 `ok`여야 하는 것이 아니며, 답변 근거가 부족하면 `needs_more_info`로 정확한 추가 설명을 요청하는 경우도 정상 응답에 포함된다고 명시돼 있다.

따라서 이번 normal case의 `needs_more_info`는 transport/contract 실패가 아니라 근거 기반 코칭 결과로 판정한다. 이를 반영해 D6 synthetic evidence의 terminal expectation을 단일 값이 아닌 허용값 목록으로 바꾼다.

- normal: `ok | needs_more_info`
- boundary: `needs_more_info`
- injection: `needs_more_info`
- failure: `unavailable`

## 함께 반영한 개선

- live Agent runner가 `D6_CASE_ID`를 받아 normal/boundary/injection 실행 증거를 구분할 수 있도록 했다.
- `D6_CASE_ID` 미지정 시 기존 호환성을 위해 `d6-normal-live-01`을 사용한다.
- `D6_CASE_ID`의 case 종류가 synthetic evidence의 허용 HTTP/terminal status와 실제 runner exit 판정에 연결되도록 보완했다. 따라서 normal live 실행의 `needs_more_info`는 기본 설정에서도 성공으로 처리되고, 허용 목록 밖 status는 실패한다.
- synthetic evidence에는 답변 원문이나 source text를 계속 저장하지 않는다.

## 1차 → 2차 비교 E2E

- 앞서 검증한 normal case를 1차 답변으로 유지하고, 코칭에서 부족하다고 표시된 개인 행동·행동 선택 이유·공고 연결을 보완한 2차 답변을 같은 연습 흐름에서 제출했다.
- 비교 화면에 1차 답변과 코칭 후 재답변이 함께 표시되는 것을 확인했다.
- 기준별 내용 비교에서 `본인이 해결 행동`은 1차 일부 확인에서 2차 확인으로, `행동 선택 이유`는 1차 미확인에서 2차 확인으로 바뀌었다.
- 비교 화면의 `여전히 부족한 설명`에는 2차 답변에서 모든 기준이 확인됐다고 표시됐다.
- 전달력 비교에는 말하기 속도 319 음절/분, 긴 침묵 0회, 반복 표현 0회가 1차와 재답변 모두 동일하게 표시됐다. 이번 검증은 동일 WAV를 재사용했으므로 동일 수치는 기대한 결과다.
- 이로써 실제 로그인 사용자 기준 1차 저장 → 1차 코칭 → 2차 저장 → 2차 코칭 저장 → 비교 렌더링까지 한 흐름을 재현했다.

MCP 운영 증거와 managed Prompt production 연결은 별도 D6 범위로 유지한다.
