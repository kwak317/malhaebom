## 1. 목적

`skills/`의 코칭·면접 대화 규칙도 기존 공고 요구사항·README Skill처럼 기능별 폴더에 두고, 실제 로더와 문서가 같은 경로를 가리키게 한다.

## 2. 작업 전 상태

- 코칭 `SKILL.md`, `criteria.json`, 두 질문 유형 문서와 `interview-conversation.md`가 `skills/` 바로 아래에 있었다.
- 공고 요구사항과 README 분석은 이미 각각의 Skill 폴더에 있었다.
- 관련 `unittest` 13개가 변경 전 컨테이너 의존성과 현재 소스의 읽기 전용 마운트에서 통과했다.
- 저장소에 다른 작업의 미커밋 변경이 다수 있어 보존했다.

## 3. 수행 내용

- 코칭 파일 네 개를 `skills/interview-coach/`에, 면접 대화 규칙을 `skills/interview-conversation/SKILL.md`에 옮겼다. 이동한 파일의 본문은 백업과 byte 단위로 동일하다.
- 코칭 로더, 면접 대화, 두 평가 runner와 설정 검사 스크립트의 기본 경로를 새 위치로 수정했다.
- README, 활성 Spec·체크포인트 링크, `CURRENT_STATE`, `ARCHITECTURE`, 저장소 구조 안내와 상위 구현 현황 문서의 트리를 실제 경로에 맞췄다. 과거 Worklog와 작업 계획의 당시 경로는 보존했다.

## 주요 판단과 이유

`problem-solving.md`, `preset-interview.md`, `criteria.json`은 독립 Skill이 아니라 코칭 묶음의 참조 파일이므로 `interview-coach/` 안에 함께 둔다. `interview-conversation`은 별도 요청·Prompt로 사용하므로 별도 폴더로 둔다. 기존 Skill 내용과 판정 버전은 변경하지 않았다.

## 6. 발견한 문제 / 남은 리스크

- 전체 테스트와 새 Docker 이미지 빌드·실행은 수행하지 않았다. 현재 실행 중인 API 컨테이너에는 이 로컬 파일 이동이 아직 반영되지 않았다.
- 추가 테스트의 첫 실행은 테스트 모듈의 절대 import를 위해 `backend/tests`를 `PYTHONPATH`에 넣지 않아 import 오류가 났다. 경로를 포함해 동일 테스트를 재실행한 결과 33개 모두 통과했다.
- 범위 밖 `.github/PULL_REQUEST_TEMPLATE.md`의 기존 trailing whitespace는 수정하지 않았다.
