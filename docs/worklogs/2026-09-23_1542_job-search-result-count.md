## 1. 목적

공고 카드가 한 건만 표시된 원인을 확인하고, 이번 달에 지원 가능한 공고도 검색해 검증된 후보가 여러 건이면 표시한다.

## 2. 작업 전 상태

- 화면과 응답 모델은 최대 3건을 받을 수 있었다. 사용자가 본 한 건은 API가 원문 검증 뒤 반환한 결과였다.
- 기본 질의가 다음 달 마감 표기에 치우쳤다. 실제 이번 달 25일 마감인 신입 백엔드 공고는 현재 원문에서 확인됐지만 해당 질의에서 누락될 수 있었다.
- 진단용 검색 1회에서 개별 공고 인용 22개 중 4개만 원문 검증을 통과했다. 검색 결과에는 마감·경력·직무·페이지 정보 확인 단계에서 걸러지는 후보가 많았다.

## 3. 수행 내용

- 기본 웹검색 질의에 이번 달과 다음 달을 모두 포함했다.
- 원문 검증과 교차 출처 중복 제거 후 3건 미만이거나 한 출처만 남을 때만 기술·서버 개발 키워드로 보완 검색한다.
- 보완 검색 후보에도 기존 URL 허용 목록, 원문 마감일·신입·백엔드 조건, README·NCS 겹침 확인을 똑같이 적용한다.
- 명세, 현재 상태, 아키텍처 기록을 실제 동작에 맞췄다.

## 5. 검증

- 관련 백엔드 테스트 12개, 전체 격리 백엔드 테스트 269개 통과.
- 지정된 GitHub README의 실제 원문과 `skill-server` 선택을 사용한 서비스 호출에서 사람인 2건·잡코리아 1건을 반환했다. 첫 공고는 README 기술 `Spring Boot`, `MySQL`과 선택 NCS 항목이 원문과 겹쳤다.
- 최종 API 이미지를 다시 빌드해 로컬 Compose에 적용했다.

## 6. 제한

- 검색 인덱스와 채용 현황이 달라지면 다음 호출에서 표시 건수가 바뀔 수 있다. 검증된 공고가 부족할 때 3건을 보장하지 않는다.
- 이 호출은 서비스 계층 검증이며 로그인한 브라우저 화면을 다시 조작한 검증은 아니다. 채팅 카드 화면은 이번 작업에서 수정하지 않았다.
