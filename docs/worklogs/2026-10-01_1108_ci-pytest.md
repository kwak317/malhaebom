## 1. 목적

Pull request Product CI가 기존 unittest 검증에 더해 `pytest`로도 백엔드 테스트를 실행하도록 구성한다.

## 2. 작업 전 상태

`.github/workflows/product-ci.yml`의 backend job은 `python -m unittest discover`만 실행했다. `backend/requirements-ci.txt`에는 pytest가 없어 CI 환경에서 pytest 명령을 보장하지 않았다.

## 3. 수행 내용

- CI 전용 의존성에 `pytest>=8,<9`를 추가했다.
- 기존 Python path·STT warm-up 비활성화 환경을 재사용해 unittest 뒤에 `python -m pytest backend/tests -q`를 실행하도록 했다.
- workflow/requirements 계약 테스트가 pytest 의존성과 실행 명령을 검사하도록 추가했다.

## 주요 판단과 이유

기존 unittest 단계는 제거하지 않았다. 현재 CI의 회귀 범위를 유지하면서 pytest 실행 증거를 추가하는 최소 변경이기 때문이다. pytest는 가벼운 테스트 의존성만 추가하며, ML runtime 패키지를 CI에 넣지 않는 정책을 유지한다.

## 4. 변경 파일

| 파일 | 변경 내용 |
| --- | --- |
| `.github/workflows/product-ci.yml` | backend job에서 unittest 다음 pytest 실행 |
| `backend/requirements-ci.txt` | CI용 pytest 의존성 추가 |
| `backend/tests/test_pr_policy_workflows.py` | workflow와 requirements 계약 검사 추가 |
| `docs/worklogs/2026-10-01_1108_ci-pytest.md` | 작업·검증·남은 확인 기록 |


## 6. 발견한 문제 / 남은 리스크

- 로컬 pytest가 `.pytest_cache` 쓰기 권한 경고를 출력한다. 테스트 결과에는 영향을 주지 않았고, CI는 새 runner에서 별도 cache 경로를 사용한다.
- unittest와 pytest가 같은 백엔드 스위트를 연속 실행하므로 CI 시간이 증가한다. 현재 목적은 checkpoint의 pytest 실행 증거 추가이며, 중복 실행 제거는 실행 시간 실측 후 별도 작업으로 판단한다.
