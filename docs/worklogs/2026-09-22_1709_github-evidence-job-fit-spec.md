# Worklog — GitHub 기술 증거 기반 공고 핏 진단 Spec

- 일시: 2026-09-22 17:09
- 작업자/에이전트: Codex
- 관련 이슈/PR: 없음
- 관련 요구사항/결정: `docs/REQUIREMENTS.md`의 공고 요구사항별 관련성·인용 검증·1/2차 비교, `docs/CONSTRAINTS.md`의 RAG 금지·사실 대필 금지·합격 가능성 판정 금지

## 1. 목적

사용자가 선택한 공개 GitHub 프로젝트에서 확인되는 기술 근거와 선택 공고의 요구사항 사이 간극을, 답변 피드백과 심층 꼬리질문으로 연결하는 신규 기능의 범위와 경쟁 서비스 대비 포지셔닝을 문서화한다.

## 2. 작업 전 상태

- 기존 문서는 공고와 답변 근거의 연결, 누락 피드백, 확인 질문, 1/2차 답변 비교를 제품 범위로 정의하고 있었다.
- 사람인의 공개 AI 모의면접 소개에서 공고 URL 기반 연습, 답변별 피드백, 실시간 행동 코칭, 답변 기반 꼬리질문을 확인했다.
- GitHub 저장소 기반 프로젝트 면접 도구·범용 코딩 에이전트·이력서 스킬 갭 도구와의 차이는 조사 전이었다.
- GitHub 프로젝트 근거를 공고 요구사항별 설명 보완에 연결하는 기능 Spec과 경쟁 비교 문서는 없었다.

## 3. 수행 내용

1. `github-evidence-job-fit` 기능의 Why·Goal·What·How·AC를 작성했다.
2. 공개 GitHub 저장소만 허용하고, 서버 구조화 추출·사용자 확인·최소 코칭 입력을 사용해 RAG와 기여 자동 단정을 피하도록 경계를 정의했다.
3. 사람인 공개 안내와 제안 기능을 비교하고, 검증 불가능한 경쟁사 기능 부재 주장을 피하는 표현 규칙을 남겼다.
4. RoundJump, GitHub Copilot, SkillBridge, GrillKit의 공개 안내·README를 조사해 GitHub 저장소 기반 질문·범용 저장소 분석·이력서 스킬 갭·문제은행 면접과의 차이를 문서화했다.

## 주요 판단과 이유

- 기능은 ‘취업에 유리한 기술 스택 추천’이 아니라 ‘선택 공고 요구와 프로젝트 기술 근거의 간극 진단’으로 한정했다. 이는 공고 밖 기술을 필수로 만들거나 전체 채용 적합성을 판정하지 않기 위해서다.
- 저장소에서 근거를 찾지 못한 상태는 경험 부재가 아니므로 `저장소 기준 미확인`으로 표현한다.
- 소스코드 전체 검색·전송 대신 허용 파일과 선택 PR·커밋의 구조화 근거만 사용한다. 팀의 RAG 금지 및 개인정보 경계를 지키기 위해서다.
- RoundJump가 공개 저장소 기반 프로젝트 질문·적응형 후속 질문을 이미 제공하므로, GitHub 연동 자체를 차별점으로 주장하지 않는다. 공고 요구사항별 근거·답변 간극의 추적과 동일 기준 재답변 비교를 차별화 경계로 정했다.

## 6. 발견한 문제 / 남은 리스크

- GitHub 공개 페이지의 실제 파일 크기·rate limit·허용 파일 목록·secret 탐지 방식은 구현 설계와 테스트로 확정해야 한다.
- 공개 저장소 원문을 외부 모델 또는 관측 서비스에 어떤 최소 형식으로 전달할지는 개인정보·보안 검토가 필요하다.
- 사람인·RoundJump 등 경쟁 서비스의 내부 기능 또는 비공개 기능은 본 비교 문서의 범위 밖이다.

## 미확인 사항

- GitHub API 인증 없이 필요한 공개 메타데이터·파일을 안정적으로 가져올 수 있는지 실행 검증하지 않았다.
- 사용자 테스트와 사람 검토를 통한 간극 상태·심층 꼬리질문의 유용성 평가는 수행하지 않았다.
