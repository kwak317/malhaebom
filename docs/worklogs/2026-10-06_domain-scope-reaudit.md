# Worklog — 도메인 확장 범위 문서 재점검

- 일시: 2026-10-06 (Asia/Seoul)
- 요청: 도메인 확장을 제품 범위 밖으로 두는 문서가 남아 있는지 다시 검토하고 필요한 부분 수정.

## 1. 목적

공고 탐색·추천·원문 수집·요구사항 분석·기업 조사·공급자 및 직무·질문 유형 확장을 일괄 제외하는 제품 문구를 제거한다. 개별 구현 작업의 범위와 원문·인용 검증 등 안전 규칙은 보존한다.

## 2. 작업 전 상태

- GitHub main `d379c9bff581272eb3921fb7034e3e2f9957db19`에는 Markdown 문서 391개가 있다. PDF·Word·RST 문서는 없으며 HTML은 프런트 진입 파일 한 개다.
- 기존 로컬 수정·미커밋 변경이 다수 존재했다. 저장소 내 현재 Markdown 566개를 검색했다. 출력·백업 사본, 의존성·평가 raw 결과는 제품 문서 검색에서 제외했다.
- GitHub 문서 중 로컬에 없는 26개는 고정 commit의 원문을 read-only로 조회해 별도로 검색했다. 기존 로컬 파일로 가져오거나 덮어쓰지 않았다.
- PRD에 원천 채용 API의 자동 수집·갱신을 포함하지 않는 문장이 남았다.
- 초기 Skill 계약 Spec의 “운영 공고 자동 수집” 제외와 초기 구현 계획의 “전역 제약”은 개별 작업의 제한이 제품 전체 제한으로 오해될 수 있었다.

## 3. 수행 내용과 주요 판단

- PRD의 자동 수집·갱신 일괄 제외 문구를 수정하고 제품 범위는 TARGET_STATE를 따르도록 명시했다.
- 미검증 검색 결과의 코칭 자동 사용 금지, 공고에 없는 조건 생성 금지는 별도 문장으로 유지했다.
- 초기 Skill 계약 Spec의 공고 수집 제외는 그 작업에서 수집 경로를 변경하지 않는다는 뜻으로 한정했다.
- 초기 분석 Skill 계획의 “전역 제약”을 “이 분석 Skill 분리 작업의 제약”으로 수정하고 출처·추천 경로 변경 제한은 당시 작업의 범위로 명시했다.
- 개별 검색 Spec의 새 공급자·새 사이트 제외는 해당 기능 변경의 범위다. 원문 검증 실패·모집 종료 공고 탈락, 평가 미포함, 과거 검증 미수행 기록도 제품 도메인 확장 금지와 구분해 보존했다.

## 5. 검증

- Markdown 전체 검색과 후보 문맥 검토, GitHub-only 26개 원문 검색 완료.
- 수정 전 사본 대비 3파일 전용 diff 검토.
- 수정된 3파일의 `git diff --check` 통과.
- TARGET_STATE 링크 3개와 안전 규칙 보존, 기존 일괄 제외 문구 삭제 검사 통과.
- 검사 결과·원문 해시·이번 변경 patch: 저장소 밖 `output/domain-scope-reaudit-side-20261006/`.
- 문서만 수정했다. 애플리케이션 테스트·E2E는 실행하지 않았다.

## 6. 발견한 문제 / 미확인 사항

기존 10월 4일 수정만으로 모든 제품 문서의 제한 문구가 제거된 것은 아니었다. 이번 재점검에서 PRD 누락을 수정했다. 현재 작업본에서 추가적인 제품 차원의 일괄 제외 문구는 발견하지 못했다. 과거 작업 범위·안전 규칙에 “제외/범위 밖”이라는 단어가 남을 수 있으며, 그 존재 자체를 제품 확장 금지로 해석하지 않는다.

GitHub main은 수정하지 않았다. PR 준비 중 확인한 결과, 10월 4일 변경은 이미 OPEN 상태인 PR #165에 포함되어 있었다. 이번 3개 문서 수정과 재감사 기록을 같은 PR에 추가한다. 구현·배포·검증 완료를 이번 문서 변경으로 주장하지 않는다.

## 7. 다음 작업

사용자의 PR 생성 승인에 따라 기존 PR #165의 깨끗한 작업 공간에서 이번 수정만 commit·push한다. 문서 전용 diff, 링크·검증 규칙 보존, PR 크기 정책을 확인하고 OPEN·non-draft·미머지 상태로 유지한다. CI·팀원 리뷰와 main 반영은 별도이며, 머지·배포는 수행하지 않는다.
