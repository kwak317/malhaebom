# Domain Research

## 목적

공개 면접 팁을 많이 모으는 것이 아니라, 신입 백엔드의 프로젝트 문제 해결 답변에서 **어떤 근거를 인정하고 무엇을 부족하다고 볼지**를 실제 사례와 사람 검토로 구체화한다.

## 현재 참고 가능한 공개 자료 유형

- 고용24 채용공고
- 워크넷 직무데이터사전
- NCS 능력단위/수행준거/KSA
- 공개 개발자 면접 질문 저장소
- 공개 합성 면접 데이터셋

이 자료들은 공고/직무/질문 범위 참고에는 쓸 수 있지만, 실제 사용자의 역할·누락·재답변 변화·면접관 판단을 대신하지 못한다.

## 도메인 지식 구축 순서

1. 팀원 각자 실제 개발 문제 사례 1건씩 정리
2. 같은 사실에서 답변 변형 생성
   - 충분한 설명
   - 이유 누락
   - 팀/개인 행동 혼동
3. 외부 검토자의 관련 경험 범위 확인
4. 모델 정답을 보여주기 전에 사례별 독립 판단 수집
5. 판단 기준 카드 작성
6. 규칙 작성에 사용하지 않은 새 사례로 대조
7. 불일치 시 규칙 수정 또는 판단 보류

## 외부 검토 질문

- 이 답변에서 실제로 확인되는 근거는 무엇인가?
- 무엇이 부족한가?
- 어떤 정보가 추가되면 판단이 바뀌는가?
- 신입에게 과한 요구는 무엇인가?
- 가장 필요한 확인 질문 하나는 무엇인가?
- 팀 행동과 개인 행동이 구분되는가?
- 결과 확인이 충분한가?
- 판단을 보류해야 하는 부분이 있는가?
