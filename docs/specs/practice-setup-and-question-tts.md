# 공고·요구사항 선택과 질문 TTS 연결

## Why

현재 연습 화면에는 질문 선택과 TTS 진입점은 있지만, 로그인 사용자가 검토된 공고와 요구사항을 선택해 서버에 고정하는 단계가 없다. 또한 핵심 질문 문구가 기획과 다르고, 기본 질문 WAV 또는 GPU TTS가 준비되지 않으면 질문을 들을 수 없다.

## Goal

로그인 사용자가 검토된 공고 1개와 해당 요구사항 1~2개를 선택하고, 기본 질문 또는 직접 입력 질문을 세션에 고정한 뒤 질문 음성을 들을 수 있게 한다.

## What

- Supabase에 검토 공고, 공고 요구사항, 24시간 연습 세션, 세션 요구사항 연결 테이블을 추가한다.
- 인증 사용자는 활성·검토 완료 공고만 조회하고 자신의 연습 세션만 생성·조회할 수 있다.
- 공고·요구사항·질문을 원자적으로 고정하는 `create_practice_session` RPC를 추가한다.
- 연습 화면을 `공고·요구사항 선택 → 질문 선택 → 녹음` 순서로 연결한다.
- `preset-04` 문구를 “프로젝트 개발 중 발생한 문제를 어떻게 해결했나요?”로 통일한다.
- 사전 생성 WAV 또는 GPU TTS가 실패하면 브라우저의 한국어 음성 합성으로 질문을 재생한다.

## How

- 프런트는 사용자 JWT로 FastAPI의 `/api/job-postings`, `/api/practice-sessions`를 호출한다.
- FastAPI는 같은 JWT를 Supabase REST/RPC에 전달해 RLS 범위 안에서만 읽고 쓴다. 서비스 역할 키는 사용하지 않는다.
- DB 함수는 `security invoker`로 실행하고 `PUBLIC`·`anon` 실행 권한을 회수한다.
- 핵심 질문의 기존 사전 생성 음성은 문구가 달라졌으므로 사용하지 않고 동적 TTS를 먼저 사용한다.

## Acceptance Criteria

1. 비로그인 사용자는 공고 목록과 세션 생성 API를 사용할 수 없다.
2. 로그인 사용자는 활성·검토 완료 공고와 요구사항을 조회할 수 있다.
3. 공고 1개와 그 공고에 속한 서로 다른 요구사항 1~2개만 세션에 저장된다.
4. 세션에는 질문 유형·질문 ID 또는 직접 입력 문구와 24시간 만료 시각이 저장된다.
5. 화면은 공고와 요구사항 선택이 끝나기 전에는 질문 단계로 진행하지 않는다.
6. 핵심 질문은 기획 문구와 정확히 일치하고 기본 선택된다.
7. 기본/직접 입력 질문 모두 TTS 재생을 시도하며 서버 음성이 실패하면 브라우저 TTS로 전환된다.
8. 기존 5~60초 녹음 흐름과 다른 화면은 회귀하지 않는다.
