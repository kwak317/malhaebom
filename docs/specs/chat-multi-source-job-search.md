# 채팅 기반 다중 출처 공고 검색

## Why

사용자는 면접 연습을 시작할 때 한 채팅 메시지로 관련 공고를 찾고 싶다. 현재는
ALIO 공고만 보여 주므로, 인사혁신처 공공취업정보와 재정경제부 공공기관 채용정보의
공고를 함께 비교해 선택할 수 없다.

## Goal

`개발관련공고`처럼 공고를 요청하는 채팅을 보내면 ALIO·인사혁신처 공공취업정보·
재정경제부 공공기관 채용정보 결과를 출처별로 보여 주고, 어느 출처의 공고를 골라도 기존의 AI 원문 분석 →
요구사항 1~2개 선택 → 면접 연습 흐름으로 이어진다.

## What

- 채팅 메시지는 LLM이 공고 검색 의도와 직무·기술 검색어로 먼저 구조화하고, 공고
  요청일 때만 세 제공자를 병렬로 조회한다.
- 결과는 `ALIO 공공기관 채용`, `인사혁신처 공공취업정보`, `재정경제부 공공기관 채용정보` 섹션으로 분리해
  각각 최대 세 건을 표시한다.
- 한 제공자 조회가 실패해도 다른 제공자의 결과는 계속 표시하고, 실패한 출처만
  채팅에서 안내한다.
- 공공취업정보 공고를 선택하면 서버가 제공자의 상세 원문을 가져와 LLM으로
  요구사항을 추출하고 근거를 검증한다. 사용자는 검증된 요구사항 중 1~2개를
  선택한다.
- API 키는 `MPO_PUBLIC_JOB_API_KEY` 환경 변수로만 사용하며 브라우저 응답이나
  로그에 노출하지 않는다.
- 재정경제부 키도 `MOFE_PUBLIC_INSTITUTION_JOB_API_KEY` 환경 변수로만 사용한다.

## How

1. LLM이 채팅 문장에서 공고 검색 여부와 짧은 직무·기술 검색어를 JSON으로 반환한다.
   모델 장애 때만 최소한의 공고 요청 판별로 검색을 계속한다.
2. 인사혁신처 공공취업정보 REST/XML 목록·상세 API와 재정경제부 공공기관 채용정보 JSON API를 서버 서비스로 감싼다.
3. 목록 API의 `serviceKey`는 데이터포털이 발급한 인코딩 값을 재인코딩하지 않고
   그대로 전송한다. 나머지 검색 값만 URL 인코딩한다.
4. 목록 API가 현재 키워드 값을 서버 측에서 필터링하지 않으므로, 최신 공고 100건의
   제목·기관·공고 분류·지원자격에서 서버가 요청 키워드를 다시 필터링한다.
5. 상세 API의 원문과 안전한 HTTPS 원문 링크를 기존 요구사항 분석 서비스에
   전달한다. 재정경제부 제공 링크가 HTTP뿐인 경우에도 분석 근거는 서버가 재조회한
   공식 API 응답이며, 저장 링크는 공식 데이터셋 HTTPS 주소를 사용한다.
6. 분석 완료 공고는 사용자 소유 `public_job` 또는 `mofe_job` 컨텍스트로 저장하고,
   해당 사용자의 연습 세션에서만 사용할 수 있게 한다.

## Acceptance criteria

- `개발관련공고` 채팅 후 세 출처의 결과 영역이 각각 표시된다.
- 어느 출처의 공고를 선택해도 AI 분석 후 요구사항 선택 화면이 이어진다.
- 한 제공자 오류가 다른 제공자의 결과를 가리지 않는다.
- 공공취업정보 키는 프런트엔드 번들과 API 응답에 포함되지 않는다.
- 백엔드·프런트엔드 관련 테스트와 프로덕션 빌드가 통과한다.

## 인천 채용정보 제외 (2026-09-23)

- 채팅 공고 검색은 위 세 출처만 조회한다. `인천 채용정보`는 호출하거나 결과에 표시하지 않는다.
- 인천 플랫폼의 타 기관 연계 공고는 해당 Open API에 포함되지 않아, 플랫폼에서 보이는
  백엔드 개발자 공고를 이 키로 찾을 수 없음을 확인했다.
- 백엔드의 인천 검색 API와 서버 전용 키 설정은 이번 채팅 범위 변경에서 제거하지 않는다.
