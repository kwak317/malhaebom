# WAV 답변 파일 업로드 Spec

## Why

- **페르소나**: 별도 환경에서 녹음한 한국어 면접 답변을 분석받고 싶은 취업준비생
- **상황**: 브라우저 마이크 녹음 대신 이미 만든 WAV 파일을 사용하고 싶다.
- **문제**: 현재 연습 화면에서는 브라우저에서 직접 녹음한 답변만 분석할 수 있다.
- **측정 지표**: 유효한 WAV 선택 후 기존 분석 Job 생성 흐름 진입 성공률 100%

## Goal

- **해결 목표**: 녹음 준비 화면에서 WAV 파일을 선택해 기존 녹음 완료·분석 흐름으로 진행한다.
- **성공 기준**: WAV 파일을 선택하면 재생 확인과 `[분석하기]`를 제공하고, 분석 요청에 원본 파일명과 WAV Blob을 전달한다.
- **Out of Scope**: WAV 이외 포맷 지원, 브라우저 내 오디오 편집·변환, 업로드 파일 길이 측정·제한, 원본 파일 장기 저장

## What

### Happy Path

1. 사용자가 `[WAV 파일 업로드]`를 누른다.
2. 사용자가 `.wav` 파일 하나를 선택한다.
3. Frontend가 파일을 재생 가능한 상태로 표시한다.
4. 사용자가 `[분석하기]`를 누르면 기존 로그인 확인과 분석 Job 생성 흐름을 실행한다.

### Edge Cases

| # | 상황 | 처리 방식 |
|---|---|---|
| EC-01 | WAV가 아닌 파일 선택 | `WAV 파일만 업로드할 수 있어요.`를 표시하고 분석을 진행하지 않음 |
| EC-02 | 파일 선택 취소 | 현재 화면 상태를 유지함 |
| EC-03 | 동일 파일 재선택 | 파일 input 값을 초기화하여 다시 선택 가능하게 함 |
| EC-04 | 비로그인 사용자가 분석 요청 | 기존 로그인 안내를 표시하고 Job을 생성하지 않음 |
| EC-05 | Backend가 파일을 거부 | Backend의 사용자용 상세 메시지를 분석 실패 화면에 표시함 |

## How

- 파일 선택 input은 `accept="audio/wav,.wav"`를 사용한다.
- Frontend는 확장자 또는 알려진 WAV MIME type을 확인한다. 최종 형식 검증은 Backend가 수행한다.
- 선택한 `File`은 `Blob`과 동일한 기존 `onAnalysis` 경로로 전달한다.
- `FormData`에는 파일의 원래 이름을 유지해 `audio` 필드로 전송한다.
- 선택 파일은 브라우저 메모리의 object URL로만 재생하며, 화면 이탈·재선택 시 URL을 해제한다.

## AC

### AC-01 · WAV 선택

- **Given**: 녹음 준비 화면
- **When**: 사용자가 `.wav` 파일을 선택함
- **Then**: `녹음 파일 업로드가 완료됐어요.`와 오디오 플레이어, `[분석하기]`가 표시됨

### AC-02 · WAV 이외 파일 차단

- **Given**: 녹음 준비 화면
- **When**: 사용자가 WAV가 아닌 파일을 선택함
- **Then**: 분석 화면으로 이동하지 않고 WAV 파일 안내 오류를 표시함

### AC-03 · 업로드 파일 분석 요청

- **Given**: 로그인 사용자와 선택된 WAV 파일
- **When**: 사용자가 `[분석하기]`를 누름
- **Then**: 기존 `POST /analysis-jobs` 요청의 `audio`가 선택 파일과 원래 파일명으로 구성됨

### AC-04 · 업로드 파일 검증 오류 표시

- **Given**: Backend가 유효하지 않은 WAV 길이·형식·용량으로 `422`와 사용자용 메시지를 반환함
- **When**: Frontend가 분석 요청 응답을 처리함
- **Then**: 공통 오류 대신 Backend가 반환한 메시지를 표시함
