# 이력서 PDF 확인 후 공고 추천

## Why
README만으로 경력·개인 역할을 알 수 없다. 사용자가 확인한 이력서 기술·프로젝트를 공고 탐색에 사용한다.

## Goal
NCS → PDF 제출/검토 → 사용자 확인 → README 선택 제출 → 추천 순서를 제공한다. 6종 정보와 페이지/인용 근거를 표시한다. 운영 배포·이력서 첨삭·채용 적합성 판정·새 DB 저장은 제외한다.

## What
지원 직무, 경력/인턴(기간·업무·형태), 기술(사용 맥락), 프로젝트(목적·역할·기능·문제 해결), 교육/졸업, 자격/어학을 추출한다. 문서에 없는 정보는 빈 항목으로 표시한다. 사용자는 각 항목 수정/삭제 후 확인한다. 원래 PDF 인용은 사용자 수정 정보와 구분한다.
개인정보(이름·연락처·상세 주소·사진·생년월일·성별)는 검토/추천 평가에 사용하지 않는다고 명시한다. 모델에 사진·메타데이터를 전송하지 않고, 알려진 연락처/명시된 개인정보 줄은 텍스트 전처리로 제거한다. 자동 완전 익명화 보장은 하지 않는다.

## How
로그인 필수 multipart POST /api/resume/analyze. 최대 5 MiB, 10페이지, 추출 문자 30,000. pypdf로 텍스트 추출, 암호화/깨진 파일/텍스트 없는 스캔/부분적으로 텍스트 없는 페이지는 명확한 오류로 반환한다. Gemini 3.1 Flash Lite(OpenRouter), 최대 출력 4,096토큰, JSON 계약 및 페이지별 원문 인용과 추출 값의 인용 내 포함 여부를 검증한다. PDF 원본·전문은 별도로 영구 저장하거나 로그하지 않는다. multipart 처리 중 임시 파일이 생길 수 있으며 요청 종료 시 업로드 파일을 닫는다.
확인된 목록은 resume_profile로 추천 요청에 선택 필드로 보낸다. 기술명은 공개 검색 키워드, 기술·프로젝트 값은 원문 매칭에 사용하며 개인정보/경력/교육은 외부 검색에 전송하지 않는다. 기존 신입 조건 검사·NCS·README 원문 검증은 유지한다. 경력/학력/자격 조건 자동 필터링은 이 변경에 포함하지 않는다. README 근거와 이력서 자기신고 매칭의 출처를 구분한다.
연습 기록 왕복은 기존 mounted 화면 유지, 공고 변경은 이력서 준비 단계도 보존한다. 로그아웃/새 연습 시 제거한다.

## AC
- Given NCS 미제출 When 화면 확인 Then PDF 제출 채팅은 없음.
- Given NCS 완료 When PDF 제출 Then 분석 결과 확인 전 README/추천을 진행하지 않음.
- Given 정상 PDF When 분석 Then 6종 항목만, 페이지/실제 인용, 고정 모델 반환.
- Given 개인정보 When 전처리/모델 추출 Then 알려진 개인정보를 제거하고 개인정보 평가를 금지.
- Given 비PDF/초과/암호화/스캔/가짜 인용/모델 실패 When 제출 Then 수정 가능한 오류, 추천 미실행.
- Given 결과 수정/삭제 후 확인 When README 건너뛰기 Then 확인한 기술/경험으로 추천 실행.
- Given 공고 변경 When 승인 Then NCS/PDF/README 보존, 이후 연습 상태만 제거.
