# 2차 녹음·답변 비교 분석 메뉴

## Why

- 사용자는 1차 코칭을 받은 뒤 같은 질문에 다시 답하고, 두 답변에서 코칭 내용이 실제로 반영됐는지 확인해야 한다.
- 현재 채팅 안의 다음 행동 버튼만으로는 재녹음과 비교 분석을 시작할 수 있는 시점을 사이드바에서 한눈에 알기 어렵다.

## Goal

- 사이드바에 `2차 녹음`, `답변 비교 분석` 메뉴를 표시한다.
- 1차 코칭 완료 뒤에만 2차 녹음을, 2차 코칭 완료 뒤에만 답변 비교 분석을 실행할 수 있게 한다.
- 기존 같은 질문·연습 세션으로 이어지는 재녹음 및 비교 화면 전환을 유지한다.

**Out of Scope**: 비교 결과의 기준 판정 변경, 새 API·DB 스키마 추가, 3차 이상 녹음, 별도 비교용 LLM 호출.

## What

**Happy Path**

1. 사용자가 1차 답변을 녹음·전사 확인하고 코칭을 완료한다.
2. `2차 녹음` 메뉴가 활성화되고, 선택하면 같은 질문의 채팅 내 재녹음을 연다.
3. 사용자가 2차 답변을 녹음·전사 확인하고 코칭을 완료한다.
4. `답변 비교 분석` 메뉴가 활성화되고, 선택하면 기존 비교 화면으로 이동한다.

**Edge Cases**

| 상황 | 처리 방식 |
| --- | --- |
| 1차 코칭 전 | 두 메뉴를 비활성화한다. |
| 2차 녹음 또는 분석 진행 중 | 중복 재녹음을 막기 위해 `2차 녹음`을 비활성화한다. |
| 2차 코칭 전 | 비교 분석을 비활성화한다. |
| 코칭 요청 실패 | 코칭 완료 상태를 기록하지 않아 다음 메뉴를 활성화하지 않는다. |

## How

- 프런트엔드에서 코칭 응답이 `ok` 또는 `needs_more_info`로 끝난 답변 차수만 완료로 기록한다.
- 1차 완료 상태는 기존 `retryAnswer`를 호출해 같은 질문의 2차 녹음 UI를 연다.
- 1·2차 완료 상태는 기존 `onComparisonRequested` 콜백을 호출한다.
- 비교 기능의 서버 호환성 및 기준별 판정 로직은 변경하지 않는다.

## AC (Given-When-Then)

- **AC-01** GIVEN 1차 코칭 전, WHEN 사이드바를 확인하면, THEN `2차 녹음`과 `답변 비교 분석` 메뉴가 비활성화되어 있다.
- **AC-02** GIVEN 1차 코칭이 정상 완료됨, WHEN `2차 녹음`을 선택하면, THEN 같은 질문의 채팅 내 녹음 UI가 열린다.
- **AC-03** GIVEN 2차 코칭이 정상 완료됨, WHEN `답변 비교 분석`을 선택하면, THEN 기존 비교 화면 전환 콜백이 실행된다.
- **AC-04** GIVEN 코칭 API가 실패함, WHEN 오류가 표시되면, THEN 해당 차수 이후 메뉴는 활성화되지 않는다.
