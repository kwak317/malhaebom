# 백엔드 공고 후보 추천

## Why

기존 공공 채용 API에서 신입 백엔드 공고가 부족하다. 사용자는 선택한 NCS 자기점검 항목과 제출한 팀 프로젝트 README를 참고해 확인할 만한 민간 채용 공고를 보고 싶다. 기존 카드에는 원문 인용과 README 문장이 길게 반복된다.

현재 검색식이 다음 달 마감 표기에 치우쳐 이번 달에 아직 지원할 수 있는 공고를 놓친다. 검색 인덱스에 남은 마감 공고가 원문 검증에서 제외되면 결과가 한 건으로 줄어들 수 있다.

Google native 검색이 정상 응답해도 개별 공고 URL citation을 0건 반환하는 사례가 있다. 이때 보완 검색까지 비면 화면에는 확인된 공고가 없다고 표시된다.
잡코리아의 일부 검증된 공고는 상세 본문에 기술 키워드가 없고 확인된 공고 제목에만 `백엔드`가 있어, 본문만 검사하면 선택 NCS 항목과의 겹침을 놓친다.

새 OpenRouter 키에서 웹검색 요청에 출력 상한이 없어 모델의 최대 65,536토큰 비용으로 사전 계산되어 402가 발생한다. 이 상태는 채팅에 일반 연결 실패로 표시된다.

README의 앞 두 기술을 하나의 따옴표 구문으로 묶으면 `"Spring Boot MySQL"`이라는 연속 문구가 없는 공고를 놓친다. `"2026-09"`처럼 날짜 형식까지 정확히 일치하도록 요구하는 검색도 점·슬래시로 마감일을 표기한 공고를 놓칠 수 있다. 보완 검색 실패를 무시하는 경로는 검색이 끝나지 않았는데도 공고 없음으로 표시한다.

`경력 무관`의 공백과 `채용 시 마감`의 날짜 없는 표기 때문에 지원 가능한 공고가 원문 검증에서 제외된다. 두 표기를 허용하되 마감·경력 제한·정보 누락 공고의 검증은 유지한다.

## Goal

- NCS 선택과 README 분석 완료 또는 건너뛰기 이후 사람인·잡코리아 웹검색으로 중복 없는 최대 3개의 백엔드 공고 후보를 채팅에 표시한다.
- 후보마다 원문 링크, 확인한 마감일 또는 `채용 시 마감`, README 분석 또는 선택 NCS 항목과 실제 공고가 겹치는 이유를 최대 두 줄로 표시한다.
- 사용자가 후보 카드의 `공고 선택`을 누르면 원문을 다시 확인하고 AI가 원문 근거가 있는 요구사항을 추출한다. 검토된 공고에서 요구사항 1~2개를 선택해 기존 질문·1차 답변·코칭·2차 답변·비교 흐름으로 이어진다.
- 범위 밖: 합격 가능성·지원 자격 충족 판정, 자동 지원, 선택하지 않은 검색 결과의 자동 저장.

## What

- 서버는 기존 `OPENROUTER_API_KEY`로 두 출처를 각각 지정한 웹검색을 수행한다. Google 검색의 도메인 필터는 지원되지 않으므로, 서버가 두 사이트의 개별 공고 링크만 허용한다. 별도 채용 사이트 API 키는 필요하지 않다.
- 서버는 검색 citation의 공고 번호를 사용해 원문 페이지를 다시 읽고 현재 날짜 기준 마감 공고와 확인 불가 공고를 제외한다.
- 2026-09-28 수정: 사람인 상세 `user_content` 영역만 분석 텍스트로 추출한다. 해당 영역이 이미지뿐이거나 20자 미만이면 추천에서 제외한다. 개인정보 안내·복리후생 등 주변 사이트 문구를 직무 요구사항의 원문으로 넘기지 않는다. 이미지 OCR은 이번 수정 범위 밖이다.
- 제출한 README 분석은 원문 SHA와 근거 인용을 다시 확인한다. 선택 NCS ID는 서버의 검토 목록과 대조한다. README 건너뛰기는 NCS만 사용한다.
- 동일 기업·동일하거나 거의 같은 제목의 두 사이트 공고는 정렬 점수가 높은 한 건만 남긴다. 현재 공고 원문에서 확인된 겹침만 짧은 추천 이유로 표시한다. 팀 README를 특정 개인의 구현·숙련도로 해석하지 않는다.
- 검색 실패·검증된 공고 없음은 별도 안내와 재시도 버튼을 제공한다.
- 검색은 오늘 이후 마감하는 이번 달과 다음 달 공고 및 원문에 `채용 시 마감`이 명시된 공고를 함께 찾고, 원문 검증에서 적은 수만 남으면 다른 검색어로 후보를 보강한다. 검증되지 않은 후보로 빈자리를 채우지 않는다.
- 기본 검색에서 검증된 후보가 0건이면 두 채용 사이트로 도메인을 제한한 별도 웹검색을 먼저 한 번 수행한다. 이후에도 3건 미만이거나 한 출처만 남으면 출처별 보완 검색을 수행한다. 후보는 같은 원문 검증과 중복 제거를 통과해야 한다.
- 검색 인용의 경유 URL과 공고 원문은 각각 제한된 수의 동시 요청으로 확인해 대기 시간을 줄인다.
- `다시 검색`은 후보 카드 아래에서 간격과 구분선을 두어 표시한다. 카드의 `공고 선택`은 검토 요청 중 중복 클릭을 막고 실패 원인을 카드 목록 아래에 표시한다.
- 채팅에 보이는 제목·진행·오류·재시도·원문 링크 문구는 `공고 검색`을 사용하고 검색 출처의 이름을 표시하지 않는다.

## How

- 인증된 `POST /api/job-search/recommendations`는 `selected_ncs_ids`, 선택적 `readme_analysis`를 받는다.
- OpenRouter `openrouter:web_search`의 Google native 검색에 `max_uses=2`, `max_tool_calls=2`를 요청하고 URL citation만 사용한다. Google의 내부 검색 횟수가 이 값으로 제한된다고 보장하지 않는다. Google 경유 주소는 리디렉션을 한 번만 확인하고 허용된 개별 공고 주소로만 정규화한다.
- 웹검색 모델 응답 출력은 요청당 최대 1,536토큰으로 제한하고 URL citation 중심의 간결한 응답을 요청한다. 402는 키의 크레딧·사용 한도 문제로 구분해 표시한다.
- 검색어에서는 마감월의 정확한 문자열 일치를 요구하지 않고, 오늘·이번 달·다음 달 조건을 지시문과 원문 마감일 검사로 적용한다. 보완 검색은 앞 두 README 기술을 별도 질의로 사용한다.
- 검색 모델이 지원하는 `reasoning.effort=low`를 사용하고 출력 상한은 유지한다. 인용 없이 `length` 또는 `tool_calls`로 끝나거나 본문이 `null`인 응답은 한 번 재시도하며, 계속 미완료이면 검색 실패로 표시한다. 최종 후보가 없고 보완 검색이 실패한 경우에도 오류를 반환한다. 이미 검증한 후보가 있으면 부분 결과를 유지한다. 빈 결과 로그에는 후보 수와 원문 검증 통과 수만 남긴다.
- 기본 질의는 이번 달과 다음 달의 개별 공고를 대상으로 한다. 검증된 결과가 0건이면 OpenRouter Exa 웹검색을 먼저 최대 1회 호출한다. 이후 3건보다 적거나 한 출처만 남았을 때 출처별 보완 질의를 수행하고 같은 검증·중복 제거 절차를 적용한다. Exa에는 `allowed_domains`와 URL 허용 목록을 함께 적용하며, 실패해도 이미 검증한 후보는 유지한다.
- `https://www.saramin.co.kr/zf_user/jobs/{view|relay/view}?rec_idx=<숫자>`와 `https://{www|m}.jobkorea.co.kr/Recruit/GI_Read/<숫자>`만 허용한다. 서버가 정규화한 URL을 조회하며 리디렉션을 따르지 않는다.
- 현재 공고 페이지의 설명 메타데이터에서 기업명·제목·경력·마감일을 추출한다. 경력은 공백을 정규화해 `경력무관`과 `경력 무관`을 동일하게 검사하고 `신입 제외`도 정규화해 거부한다. 검색 질의에도 두 경력 표기를 포함한다.
- 원문 마감일 필드의 `채용시마감`·`채용 시 마감`은 날짜 없이 허용하고 응답의 필수 `deadline` 필드는 `null`로 반환한다. 날짜가 있으면 기존 날짜 문자열을 반환한다. 마감 표기가 누락되거나 미정·잘못된 날짜이면 제외하고, 마감 날짜가 지났거나 페이지에 마감 안내가 있으면 `채용 시 마감` 공고도 거부한다. 백엔드 업무 조건은 유지한다.
- 카드에서 `deadline=null`은 `채용 시 마감`으로 표시한다. 실제 날짜를 임의로 만들지 않는다. 정렬 점수가 같은 경우 날짜가 있는 공고를 마감일 순으로 먼저 표시하고 날짜 없는 공고는 뒤에 둔다. 공고 선택 시에도 같은 원문 검증을 다시 적용한다.
- 현재 공고 원문에서 확인한 README 기술·기능 키워드와 NCS 키워드 겹침을 기준으로 정렬한다. 정렬 뒤 회사명과 제목을 정규화해 교차 출처 중복을 제거한다. 서로 다른 검증 공고가 있으면 각 출처에서 한 건씩 우선 포함하고 남은 자리를 점수순으로 채운다. 점수는 내부 정렬에만 사용하고 적합성 점수로 노출하지 않는다.
- 키워드 겹침은 검증한 공고 제목과 상세 본문에서 확인한다. 제목의 `백엔드`도 선택 NCS 서버 구현 항목과의 근거가 될 수 있다.
- 사람인 `user_content`가 있으면 그 안의 표시 텍스트만 사용하고 script/style/noscript는 제외한다. 본문이 비어 있을 때 주변 텍스트로 대체하지 않는다. 구형 페이지는 기존 상세요강~근무지위치 범위를 사용하되 개인정보 안내·복리후생 시작점에서 자른다. 모집 상태·신입 조건·원문 인용 검증과 선택 전 저장 금지는 유지한다.
- 카드에는 회사·직무·경력·마감일, 근거 항목을 축약한 `추천 이유`, 원문 링크와 `공고 선택`을 표시한다. 제출된 README와 직접 겹친 항목이 없으면 그 사실을 짧게 표시한다. 공고 본문·README 인용을 그대로 길게 표시하지 않는다.
- 검색 후보는 선택 전에는 메모리 응답만 사용한다. 인증된 `POST /api/job-search/recommendations/analyze`가 선택 URL을 받으면 서버가 지원 도메인과 개별 공고 번호를 확인하고 현재 원문에서 마감·신입·상세 내용을 다시 검증한다. AI 요구사항의 원문 인용을 서버에서 대조한 뒤에만 소유자별 `private_job` 검토 공고와 요구사항을 저장한다.
- 선택된 검토 공고는 기존 `GET /api/job-postings` 목록과 세션 생성 계약을 사용한다. RLS는 공고·요구사항·세션을 해당 사용자에게만 노출한다. 같은 사용자가 같은 공고를 다시 선택하면 검토 결과를 재사용하되 현재 공고 상태는 다시 확인한다.

## AC

- Given 사람인 상세가 이미지뿐이고 주변에 개인정보 안내/복리후생이 있을 때, When 추천·선택 검증, Then 추천하지 않고 선택 시 원문 상세 텍스트 확인 실패를 안내한다. LLM·저장은 호출하지 않는다.
- Given 사람인 상세에 업무·자격요건 텍스트가 있을 때, When 추출, Then 그 본문만 분석에 넘기며 주변 사이트 문구와 숨겨진 지시문은 포함하지 않는다.

- Given 유효한 NCS 선택과 README 분석, When 추천 요청, Then 근거가 겹치고 마감일이 남거나 원문에 채용 시 마감이 명시된 두 출처의 백엔드 공고를 중복 없이 최대 3건 반환한다.
- Given 동일 기업의 같은 공고가 두 출처에 있을 때, When 결과를 정렬함, Then 점수가 높은 한 건만 반환한다.
- Given 공고 카드 표시, When 추천 근거를 읽음, Then README·NCS에서 실제 겹친 항목을 간단히 표시하고 README 직접 일치가 없으면 그 상태를 밝히며 원문 인용은 표시하지 않는다.
- Given 마감되거나 외부 도메인·목록 페이지 링크, When 검색 결과에 포함, Then 반환하지 않는다.
- Given README SHA 또는 인용 불일치·알 수 없는 NCS ID, When 요청, Then 검색 전에 거부한다.
- Given README 건너뛰기, When NCS 선택 후 요청, Then NCS만으로 후보를 찾는다.
- Given 웹검색 실패 또는 검증된 후보 0건, When 채팅을 표시, Then 실패와 빈 결과를 구별하고 다시 검색할 수 있다.
- Given 일시적인 검색 상위 서비스 오류, When 웹검색을 호출, Then 서버가 한 번 재시도하고 실패하면 출처 이름 없는 오류를 표시한다.
- Given 이번 달에 유효한 공고와 다음 달에 유효한 공고가 함께 있을 때, When 검색 후보를 수집함, Then 두 달을 모두 검색 대상으로 삼고 원문 검증을 통과한 서로 다른 공고만 반환한다.
- Given 기본·보완 검색의 검증된 공고가 부족할 때, When 제한된 도메인의 추가 웹검색이 개별 공고 URL을 반환함, Then 원문 검증과 중복 제거를 통과한 후보만 결과에 추가한다.
- Given 검증된 공고의 제목에만 `백엔드`가 있을 때, When 사용자가 서버 구현 NCS 항목을 선택함, Then 제목을 근거로 해당 항목과의 겹침을 표시한다.
- Given 사용 가능한 크레딧이 모델 기본 최대 출력 비용보다 적을 때, When 공고 웹검색을 호출함, Then 출력 상한을 명시해 과도한 비용 예약을 피한다. 실제 잔액·키 한도 부족으로 402가 나면 일반 연결 실패 대신 한도 안내를 표시한다.
