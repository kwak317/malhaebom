# 1차·2차 답변 근거 비교

## Why

현재 비교 화면은 CPM·긴 침묵·반복 표현의 절대 수치만 보여주며, 수치가 늘어난 경우에도 줄었다는 고정 문구를 표시한다. 두 답변에서 어떤 설명이 추가됐는지, 같은 기준에서 무엇이 여전히 확인되지 않는지, 원문 근거와 모순 판정이 무엇인지 확인할 수 없다.

## Goal

같은 질문의 두 답변을 각각 독립적으로 분석한 저장 결과를 서버 규칙으로 비교해 기준별 상태·원문 근거·추가된 설명·남은 부족 항목·각 답변에서 확인된 모순을 보여준다. 전달력 지표는 증가·감소·동일만 설명하고 합격 가능성이나 실제 역량 향상을 판정하지 않는다.

## What

- 답변 내용 분석 결과에 고정 기준 ID, 상태, 답변 원문 인용과 모순 정보를 저장한다.
- 1차와 2차에 같은 기준 ID가 있을 때만 서버에서 상태 변화를 계산한다.
- `not_observed/undetermined → met`만 추가된 설명으로 분류한다.
- 2차가 `met`이 아닌 항목은 여전히 채울 설명으로 표시한다.
- 모순은 각 답변을 독립 분석할 때 확인된 상충 인용만 표시한다.
- CPM·긴 침묵·반복 표현은 증가·감소·동일이라는 실제 변화만 표시한다.

## How

- MCP 도구 계약은 `compare_attempts(context_token, previous_coaching_run_id, current_coaching_run_id)`다. `context_token`은 FastAPI가 사용자·두 코칭 결과 ID·읽기 scope·5분 이하 만료를 고정해 발급한다.
- MCP 저장소는 두 `coaching_runs`과 연결된 `answer_revisions`·`analysis_jobs`만 읽고, 서비스가 소유자·만료·완료 상태를 다시 검사한다.
- 비교 전에 같은 연습 세션·질문·공고 snapshot·model·Prompt·Skill 버전인지 검사하고, 인자 순서가 1차→2차인지 확인한다.
- 내용 분석 모델은 답변에 실제로 포함된 정확한 부분 문자열만 근거로 반환한다.
- 서버는 저장된 두 분석 결과를 비교하며 비교 단계에서 LLM을 다시 호출하지 않는다.
- 기준 ID 집합이 다르거나 구조화 분석이 없으면 내용 비교 불가 사유를 명시하고 전달력 수치만 비교한다.
- 응답은 기준별 상태·인용·부족 설명과 CPM·긴 침묵·반복 방향만 반환하고, 전체 전사문·사용자 ID·저장소 내부 경로는 반환하지 않는다.
- 화면은 기준별 1차·2차 상태와 인용을 나란히 표시하고, 자동 비교가 사실 여부나 역량 향상을 증명하지 않는다는 경계를 함께 표시한다.

## Acceptance Criteria

1. 기준별 1차·2차 상태와 각 답변에 속한 원문 인용을 표시한다.
2. 새로 `met`이 된 항목과 2차에서도 `met`이 아닌 항목을 구분한다.
3. 각 답변 분석에서 `undetermined`로 판정된 상충 인용을 표시한다.
4. 기준 ID 집합이 다르면 상태를 억지로 연결하지 않고 비교 불가로 처리한다.
5. 전달력 지표가 증가·감소·동일한 경우 각각 실제 방향에 맞는 문구를 표시한다.
6. 수치가 감소하거나 기준 상태가 바뀌어도 합격 가능성·실제 역량 향상·코칭 인과 효과를 판정하지 않는다.
7. 비교 계산은 저장된 결과만 사용하며 추가 LLM 호출을 하지 않는다.
8. 타 사용자·만료·미완료 결과와 capability token이 허용하지 않은 결과 ID는 조회하지 않는다.
9. 세션·질문·공고·model·Prompt·Skill 조건이 다르면 비교를 거절한다.
