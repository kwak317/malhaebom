# TTS 100개 테스트 템플릿 카탈로그 Spec

## Why

- **페르소나**: 혼자 면접 답변의 전달 방식을 연습하는 한국어 취업준비생
- **상황**: 분석 결과에서 말속도·긴 침묵·반복 표현 등을 확인한 뒤, 짧고 일관된 코치 음성으로 바로 다음 행동을 이해해야 한다.
- **문제**:
  1. 코치 발화 템플릿 90개는 초안으로 고정됐지만 수용된 코치 WAV가 없어 앱은 문제 코드별 텍스트 폴백을 사용한다.
  2. 질문·피드백 문구를 문서에 흩어 두면 앱이 어떤 항목을 선택해야 하는지 테스트할 수 없다.
  3. Candidate01 코치는 빠른 속도와 마지막 음절 잘림 이력이 있어, 문구별 생성·청취 검수 전에는 앱 재생 대상으로 둘 수 없다.
- **측정 지표**: 카탈로그 항목 수 100개, 역할·문제 코드별 수량 정확도 100%, 선택 테스트 통과율 100%, 수용되지 않은 음성의 앱 재생 건수 0건

## Goal

- **해결 목표**: 질문자 10개와 코치 90개, 총 100개의 한국어 고정 텍스트 템플릿을 역할·문제 코드·검수 상태가 있는 버전 관리 카탈로그로 관리한다.
- **성공 기준**:
  - 질문자 10개, 코치 문제 코드별 18개(5종), 총 100개를 정확히 기록한다.
  - 앱 선택 계약은 기본 질문 1개 또는 허용된 문제 코드 최대 2개에 대해 템플릿 ID를 결정적으로 반환한다.
  - `accepted`가 아닌 항목 또는 연결된 정적 WAV가 없는 항목은 재생하지 않고 텍스트 안내로 대체한다.
  - 검증 스크립트가 JSON 형식·수량·중복·허용 코드·선택 계약을 검사한다.
- **Out of Scope**: Qwen 실시간 합성, 모델 재학습, 생성 WAV·checkpoint·원본 또는 파생 음성의 GitHub 저장, 사용자 답변·전사문을 입력으로 한 개인화 문장 생성, 질문 내용의 정답·합격 가능성 평가, 프런트엔드·백엔드 프레임워크 선택

## What

### Happy Path

1. 팀원은 버전 관리되는 카탈로그에서 10개 기본 질문자 문구와 90개 코치 문구를 확인한다.
2. 앱 어댑터는 기본 질문 ID 또는 분석 결과의 허용 문제 코드 0~2개를 전달한다.
3. 선택 계약은 입력 순서대로 해당 역할의 `accepted` 기본 템플릿만 최대 두 개 반환한다.
4. 앱은 검수 완료된 정적 WAV 참조가 있는 템플릿만 재생하고, 나머지는 같은 `displayText`를 텍스트로 표시한다.
5. 로컬 TTS 담당자는 `draft` 문구를 생성·청취 검수한 뒤에만 `accepted`와 정적 WAV 참조를 별도 배포 환경에 등록한다.

### 카탈로그 구성

| 역할 | 구분 | 수 | 앱 연결 방식 |
|---|---|---:|---|
| 질문자 | 신입 개발자 기본 면접 질문 | 10 | 질문 ID별 1개 |
| 코치 | `SPEED_FAST` | 18 | 수용된 기본 문구 1개 |
| 코치 | `LONG_SILENCE` | 18 | 수용된 기본 문구 1개 |
| 코치 | `FILLER_REPEAT` | 18 | 수용된 기본 문구 1개 |
| 코치 | `LOW_VOLUME` | 18 | 수용된 기본 문구 1개 |
| 코치 | `TERMINAL_INTONATION` | 18 | 수용된 기본 문구 1개 |
| 합계 |  | **100** | 분석 결과당 최대 2개 |

### Edge Cases

| # | 상황 | 처리 방식 |
|---|---|---|
| EC-01 | 허용되지 않은 문제 코드 | 해당 코드는 무시하고 텍스트 안내만 표시한다. |
| EC-02 | 문제 코드가 3개 이상 | 분석 어댑터가 우선순위 순서대로 최대 2개만 전달한다. |
| EC-03 | `draft` 또는 `rejected` 템플릿 | WAV를 재생하지 않고 `displayText`만 표시한다. |
| EC-04 | `accepted`이지만 정적 WAV 참조가 없음 | WAV를 재생하지 않고 배포 설정 오류를 기록한다. |
| EC-05 | 카탈로그 중복 ID·중복 문구·잘못된 역할 | 카탈로그 검증이 실패하며 앱 배포 대상에서 제외한다. |
| EC-06 | 사용자 전사문·수치가 템플릿 입력으로 전달됨 | 계약 위반으로 처리하며 고정 템플릿만 사용한다. |

## How

### 저장소 파일 경계

- `configs/tts/tts_template_catalog.json`: 템플릿 100개의 비민감 텍스트·역할·문제 코드·검수 상태를 담는다.
- `configs/tts/tts_template_selection_cases.json`: 선택 계약의 입력·예상 템플릿 ID·텍스트 대체 결과를 담는다.
- `tests/tts/test_tts_template_catalog.py`: Python 표준 라이브러리 `unittest`로 JSON의 형식·수량·선택 사례를 검사한다.
- 실제 WAV의 위치·hash·수동 청취 기록은 공개 저장소에 넣지 않는다. 라이선스·보관 권한이 확인된 배포 환경에서만 `accepted` 항목과 연결한다.

### 템플릿 레코드 계약

각 레코드는 아래 값을 가진다.

```json
{
  "templateId": "coach-speed-fast-01",
  "speakerRole": "coach",
  "speakerId": "candidate_01_coach",
  "issueCode": "SPEED_FAST",
  "displayText": "문장 끝을 또렷하게 마무리하며, 한 문장씩 천천히 말해 보세요.",
  "qcStatus": "draft",
  "isPrimary": false,
  "audioAssetId": null
}
```

- 질문자 레코드는 `speakerRole: "questioner"`, `speakerId: "candidate_04_questioner"`, `questionId`를 가진다. `issueCode`는 없다.
- 코치 레코드는 `speakerRole: "coach"`, `speakerId: "candidate_01_coach"`, 허용된 `issueCode`를 가진다.
- `qcStatus`는 `draft`, `accepted`, `rejected` 중 하나다. 현재 질문자 10개는 개인 Supabase 검증 기준 `accepted`이고, 코치 90개는 모두 `draft`다.
- `isPrimary`는 같은 질문 ID 또는 같은 문제 코드 안에서 수용된 재생 대상 1개에만 `true`로 바꿀 수 있다.
- `audioAssetId`는 수용된 정적 WAV를 가리키는 비민감 식별자다. 초기값은 `null`이며, 실제 URL·로컬 절대 경로·WAV hash는 이 저장소에 기록하지 않는다. 배포 환경은 이 식별자를 허용된 비공개 자산 위치로 해석한다.
- 모든 문구는 한국어를 기본으로 하고, 기술 용어가 필요할 때만 문장 안에 영어 전문용어를 그대로 쓴다. 개인 이름·사용자 전사문 변수·점수·합격 판단 문구는 넣지 않는다.

### 선택 계약

```text
입력: questionId 1개 또는 issueCodes 0~2개(우선순위 순서)
출력: accepted + isPrimary + 정적 WAV 참조가 모두 있는 템플릿 ID 목록
제한: 코치는 입력 순서를 보존하며 최대 2개, 그 외에는 displayText만 반환
```

- `questionId` 입력은 수용된 질문자 기본 템플릿 1개만 선택한다.
- 코치 입력은 각 문제 코드의 수용된 기본 템플릿만 선택한다.
- 고정 문구만 사용한다. 사용자 음성·전사문·개인별 수치를 Qwen 또는 문구 변수에 전달하지 않는다.
- 앱 프레임워크가 정해지기 전에는 이 JSON 계약과 테스트 사례를 공유 기준으로 사용한다. 구현 언어가 정해진 뒤에도 같은 선택 결과를 재현해야 한다.

## AC (Given-When-Then)

### AC-01 · 100개 카탈로그 수량

- GIVEN: 템플릿 카탈로그가 준비되었을 때
- WHEN: 검증 스크립트를 실행하면
- THEN: 질문자 10개와 코치 90개, 문제 코드별 18개, 총 100개임을 확인한다.

### AC-02 · 레코드 형식과 안전한 문구

- GIVEN: 카탈로그의 각 템플릿 레코드가 있을 때
- WHEN: 검증하면
- THEN: 고유 `templateId`, 올바른 역할·화자·허용 코드·검수 상태를 가지며, 사용자 전사문 변수나 개인별 점수를 포함하지 않는다.

### AC-03 · 문제 코드 선택

- GIVEN: `SPEED_FAST`, `LONG_SILENCE`가 우선순위 순서로 입력되었을 때
- WHEN: 선택 계약을 검증하면
- THEN: 해당 순서의 수용된 코치 기본 템플릿을 최대 두 개 반환하거나, 수용본이 없으면 두 문구의 텍스트 대체 결과를 반환한다.

### AC-04 · 코치 수용 전 WAV 미재생

- GIVEN: 코치 항목이 `draft`이고 정적 WAV 참조가 없을 때
- WHEN: 앱 어댑터가 선택하면
- THEN: 코치 WAV 재생 대상은 0개이고 텍스트 안내만 반환한다.

### AC-05 · 질문자 선택

- GIVEN: 등록된 기본 질문 ID가 입력되었을 때
- WHEN: 선택 계약을 검증하면
- THEN: 해당 질문자 템플릿 1개만 반환하거나 수용 WAV가 없으면 텍스트 대체 결과를 반환한다.

### AC-06 · 카탈로그 오류 차단

- GIVEN: 허용되지 않은 문제 코드, 중복 ID, 중복 문구, 잘못된 수량 중 하나가 있을 때
- WHEN: 검증 스크립트를 실행하면
- THEN: 실패 사유를 표시하고 카탈로그를 앱 통합 대상으로 인정하지 않는다.
