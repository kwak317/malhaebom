# UI 테마 및 코칭 화면 새로고침 Spec

## Why

- **페르소나**: 면접 답변을 반복 연습하는 신입 백엔드 개발자 준비생.
- **상황**: 첫 진입, 녹음, 전사 단계에서 현재 기능의 목적과 진행 상태를 빠르게 파악해야 한다.
- **문제**: 현재 화면은 제공된 목표 디자인의 일관된 시작 경험·시각적 진행 상태·라이트/다크 테마 선택을 제공하지 않는다.
- **측정 지표**: 기존 연습 시작·녹음·전사·기록 이동 회귀 0건, 라이트/다크 전환 후 선택 테마 유지, 키보드와 스크린 리더에서 테마 토글 식별 가능.

## Goal

- **해결 목표**: 목표 디자인을 바탕으로 시작 메인과 코칭 중 녹음/전사 화면을 갱신하고, 전역 라이트/다크 테마를 제공한다.
- **성공 기준**:
  - 첫 진입 시 새 메인이 표시되고 연습 시작 및 기록 이동이 기존 경로로 동작한다.
  - 헤더의 내 계정 옆 원형 테마 버튼이 라이트/다크를 전환하고, 툴팁·접근 가능한 이름을 제공한다.
  - 사용자가 고른 테마는 다음 페이지 방문에도 유지하며, 선택 전에는 OS 선호 테마를 따른다.
  - 녹음 중과 전사 중에 각각 전용 마스코트 이미지를 표시하되 기존 녹음·전사 상태 전이와 API 호출을 변경하지 않는다.
  - 기존 연습 기록 화면의 정보 구조와 API 동작은 바꾸지 않는다.
- **Out of Scope**: 백엔드/API/DB 변경, 녹음·STT·코칭 정책 변경, 기록 화면의 시각 재설계, GCP 배포 설정 변경, 실제 사용자 데이터 수집.

## What

### Happy Path

1. 사용자가 앱에 처음 진입하면 새 메인에서 서비스 목적, 연습 시작, 기록 확인을 본다.
2. 사용자가 `연습하기`를 선택하면 기존 연습 설정과 코칭 흐름으로 이동한다.
3. 헤더의 원형 테마 버튼을 누르면 즉시 라이트/다크가 전환되고, 다음 방문에도 그 선택이 유지된다.
4. 답변 녹음 중에는 녹음용 마스코트·시간·상태를, 전사 중에는 전사용 마스코트·진행 상태를 표시한다.
5. 사용자가 `연습 기록`을 선택하면 기존 기록 화면과 데이터 조회 동작을 그대로 이용한다.

### Edge Cases

| 상황 | 처리 |
| --- | --- |
| 저장된 테마 값이 없거나 유효하지 않음 | `prefers-color-scheme`을 따르고 라이트를 최종 fallback으로 사용 |
| 브라우저 저장소 접근 실패 | 현재 세션에서 전환은 유지하고 저장 실패 때문에 화면을 막지 않음 |
| 마스코트 이미지 로드 실패 | alt 텍스트와 상태 텍스트는 유지하고 레이아웃이 무너지지 않게 함 |
| 마이크 권한 거부·녹음 오류 | 기존 오류 메시지·재시도 동작을 유지 |
| 작은 화면 | 헤더 메뉴와 테마 토글이 겹치지 않고 기존 반응형 흐름을 유지 |

## How

- React Context/hook으로 `light | dark` 테마 상태를 제공하고, `document.documentElement.dataset.theme`에 적용한다.
- CSS custom property로 `page`, `surface`, `text`, `border`, `brand`, `focus`, `status` 색상 토큰을 정의한다. 기존 CSS의 직접 색상은 변경 범위 화면부터 토큰으로 치환한다.
- 테마 선택은 개인 정보와 무관한 UI 선호값으로만 브라우저 저장소에 보관한다. 서버·Supabase에는 저장하지 않는다.
- 공통 `AppHeader`에 원형 버튼을 추가하며, 현재 모드의 반대 전환 목적을 `aria-label`과 hover/focus 툴팁으로 제공한다.
- 새 시작 메인은 기존 `practice` 및 `history` navigation callback만 호출한다. 코칭 workspace의 녹음/전사 상태에는 새 마스코트 asset만 연결한다.
- 마스코트 asset은 첨부 시안을 **참고 이미지**로만 사용해 투명 배경 PNG 두 장(녹음·전사)을 새로 생성한다. 스크린샷을 잘라 제품 asset으로 사용하지 않는다.
- 롤백은 기능 브랜치/PR 단위로 `git revert`하고, Vercel은 이전 정상 commit을 재배포한다. 백엔드 배포는 하지 않는다.

## AC

### AC-01 · 시작 메인 진입

- GIVEN: 사용자가 기본 앱 경로에 접속했다
- WHEN: 앱 로딩이 끝난다
- THEN: 새 메인과 `연습하기`, `기록 확인하기` 행동이 표시되고 각각 기존 practice/history 경로로 이동한다.

### AC-02 · 테마 전환과 유지

- GIVEN: 사용자가 라이트 또는 다크 테마를 보고 있다
- WHEN: 내 계정 옆 테마 토글을 누른다
- THEN: `html[data-theme]`와 화면 색상이 반대 테마로 즉시 바뀌고, 새로 고침 뒤에도 같은 선택이 적용된다.

### AC-03 · 툴팁과 접근성

- GIVEN: 키보드 또는 마우스로 테마 토글에 focus/hover 한다
- WHEN: 토글을 확인한다
- THEN: 다음 동작을 설명하는 툴팁과 접근 가능한 이름을 얻는다.

### AC-04 · 코칭 상태 이미지

- GIVEN: 사용자가 답변을 녹음하거나 전사 처리를 기다린다
- WHEN: 기존 상태가 `recording` 또는 전사 대기 상태가 된다
- THEN: 해당 상태의 전용 마스코트와 기존 상태 텍스트가 나타나며, 녹음 중지·오류·재시도 동작은 기존과 동일하다.

### AC-05 · 기록 회귀 없음

- GIVEN: 로그인한 사용자가 연습 기록으로 이동한다
- WHEN: 기록을 조회하거나 결과 보기를 선택한다
- THEN: 기존 기록 조회·상세 이동·삭제 동작이 유지된다.

### AC-06 · 롤백 가능성

- GIVEN: UI 변경이 배포된 뒤 회귀가 확인된다
- WHEN: 담당자가 변경 PR을 revert하고 이전 Vercel commit을 재배포한다
- THEN: 데이터 마이그레이션 없이 이전 UI와 기능 경로로 돌아갈 수 있다.
