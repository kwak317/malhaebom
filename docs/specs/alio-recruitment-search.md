# ALIO 공고 검색

## Why

- **페르소나**: 신입 백엔드 개발자 공고를 찾아 면접 연습을 준비하는 사용자
- **상황**: 연습 조건 화면에서 이미 검토된 공고를 선택하기 전에, 현재 진행 중인 공공기관 공고를 ALIO에서 확인하고 싶다.
- **문제**: 별도 사이트로 이동해 공고를 찾고 다시 서비스로 돌아와야 하며, ALIO 인증키를 브라우저에 노출하지 않고 조회할 경로가 없다.
- **측정 지표**: 로그인 사용자가 연습 조건 화면에서 검색어 1회 입력으로 ALIO 진행 공고 목록과 출처 링크를 확인한다.

## Goal

- **해결 목표**: 인증된 사용자가 공고 선택 화면에서 제목 키워드로 진행 중인 ALIO 공고를 최대 10건까지 조회한다.
- **성공 기준**: 검색 요청은 FastAPI만 ALIO 인증키를 사용하며, 브라우저 응답·로그·오류 메시지에는 인증키가 포함되지 않는다.
- **Out of Scope**: 검색 결과의 자동 DB 저장, `reviewed` 전환, 요구사항 자동 추출, 검색 결과로 연습 세션 생성, 공고 추천·순위화.

## What

**Happy Path**

1. 로그인 사용자가 공고 선택 화면에서 제목 키워드를 입력하고 검색한다.
2. React가 Bearer 토큰으로 `GET /api/alio/recruitments`를 호출한다.
3. FastAPI가 서버 환경변수의 ALIO 인증키를 포함해 ALIO 채용 목록을 조회한다.
4. 화면은 기관명, 제목, 마감일, 근무지, 고용·경력 구분과 원문 출처 링크를 표시한다.
5. 사용자는 원문을 확인한 뒤, 아래의 검토 완료 공고 중 하나를 기존 방식으로 선택해 연습을 진행한다.

**Edge Cases**

| # | 상황 | 처리 방식 |
| --- | --- | --- |
| EC-01 | 비로그인 요청 | FastAPI가 401을 반환하고 기존 로그인 안내를 유지한다. |
| EC-02 | 빈 문자열 또는 80자 초과 검색어 | 프런트가 요청하지 않고 안내를 표시하며, 서버도 422로 검증한다. |
| EC-03 | `ALIO_API_KEY` 누락 | 서버는 503과 설정 안내를 반환하며 키 값을 노출하지 않는다. |
| EC-04 | ALIO 타임아웃·5xx·형식 오류 | 서버는 503과 재시도 안내를 반환한다. |
| EC-05 | 검색 결과 없음 | 200과 빈 목록을 반환하고 화면에 결과 없음을 표시한다. |
| EC-06 | 출처 URL이 HTTP(S)가 아님 | 해당 결과의 출처 링크를 생략한다. |

## How

```text
GET /api/alio/recruitments?query={1..80자}&page=1
인증: Bearer JWT (필수)

응답 200:
{
  "query": "백엔드",
  "page": 1,
  "page_size": 10,
  "total_count": 1,
  "recruitments": [{
    "announcement_id": 123456,
    "company": "기관명",
    "title": "공고 제목",
    "source_url": "https://...",
    "announced_at": "2026-09-21",
    "deadline": "2026-10-06",
    "location": "서울",
    "employment_type": "정규직",
    "recruitment_type": "신입"
  }]
}

오류: 401(로그인 필요), 422(검색어 검증), 503(ALIO 설정·외부 요청 실패)
```

- 키는 `.env`의 `ALIO_API_KEY`에만 둔다. `VITE_` 환경변수·프런트 요청·응답에는 포함하지 않는다.
- 기본 조회 URL은 ALIO의 공개 채용 조회 URL이며, API 활용신청 화면의 정식 URL이나 키 파라미터명이 다를 경우 `ALIO_RECRUITMENT_API_URL`, `ALIO_API_KEY_PARAM`으로 서버에서만 교체한다.
- 외부 검색 결과는 검토 전 자료다. 기존 Supabase의 `review_status=reviewed` 공고 목록과 연습 세션 생성 계약은 변경하지 않는다.

## AC (Given-When-Then)

**AC-01 · 인증된 ALIO 검색**
- GIVEN: 유효한 로그인 토큰과 `ALIO_API_KEY`가 있다.
- WHEN: 사용자가 `백엔드`로 검색한다.
- THEN: 서버가 인증키를 포함한 ALIO 요청을 보내고 정규화한 결과만 반환한다.

**AC-02 · 키 비노출**
- GIVEN: 프런트가 ALIO 검색 API를 호출한다.
- WHEN: 네트워크 요청과 응답을 확인한다.
- THEN: 브라우저 요청·응답에 `ALIO_API_KEY` 값이 없다.

**AC-03 · 검토 경계 보존**
- GIVEN: ALIO 검색 결과가 표시된다.
- WHEN: 사용자가 기존 공고 선택·연습 세션 생성 흐름으로 진행한다.
- THEN: 기존처럼 Supabase의 검토 완료 공고와 그 요구사항 1~2개만 세션에 저장된다.

**AC-04 · 외부 실패 안내**
- GIVEN: ALIO 인증키가 없거나 외부 서비스가 응답하지 않는다.
- WHEN: 사용자가 검색한다.
- THEN: 키 값 없이 재시도 가능한 안내가 표시되고 기존 검토 공고 선택은 계속 사용할 수 있다.
