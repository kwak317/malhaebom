# 채팅 시작 시 백엔드 개발 역량 선택

## Why

- 신입 백엔드 개발자 준비생이 공고를 찾기 전에 직무 관련 역량을 떠올릴 수 있도록 돕는다.
- 발급받은 NCS 기준정보 조회 API는 응용SW엔지니어링의 능력단위명·정의를 제공하지만 지식·기술·태도(KSA) 분류 항목은 제공하지 않는다. 따라서 출처와 말해봄의 해석을 구분해야 한다.

## Goal

- 로그인 사용자가 연습 채팅을 열면 NCS 능력단위를 조회해 백엔드 개발 관련 지식·기술·태도 선택지 각 3개를 하나의 코치 메시지에 표시한다.
- 사용자는 보유했다고 생각하는 항목을 여러 개 선택해 현재 채팅에 한 번 보낼 수 있다.
- **Out of Scope**: 선택을 역량 검증·기업 채용요건으로 표시하기, 코칭 점수·판정에 반영하기, DB 저장, 별도 KSA 원문 API 연동.

## What

1. 서버가 `NCS_API_KEY`로 NCS 기준정보 `NCS005`에서 `20 정보통신 > 01 정보기술 > 02 정보기술개발 > 02 응용SW엔지니어링`의 최신 능력단위를 조회한다.
2. 검토한 능력단위 코드에 연결된 말해봄 작성 지식·기술·태도 자기점검 항목만 반환한다. 메시지에 NCS 능력단위 출처와 분류 항목의 작성 주체를 구분해 표시한다.
3. 사용자는 항목을 복수 선택하고 `선택 완료`를 눌러 현재 채팅에 자신의 선택을 표시한다. 공고 검색 흐름은 계속 사용할 수 있다.

**예외**

- 키가 없거나 NCS 조회가 실패하면 선택지를 만들어내지 않고 오류와 재시도 동작을 보여 준다.
- 로그아웃 상태에서는 키를 사용하는 NCS API를 호출하지 않고 로그인 안내를 표시한다.
- 제공자 응답의 직무 분류가 다르거나 최신 능력단위가 아니면 선택지 근거로 사용하지 않는다.

## How

- 서버 전용 `GET /api/ncs/backend-competencies`는 기존 Bearer 인증을 사용한다.
- 키는 루트 `.env`의 `NCS_API_KEY`에서만 읽는다. 브라우저 요청·응답·로그에 키를 포함하지 않는다.
- `NCS005` 응답의 능력단위 코드·명칭·정의를 검사하고, 미리 검토한 코드에만 자기점검 항목을 연결한다. 버전 suffix는 제공자의 최신 값을 사용한다.
- 프런트엔드는 채팅 시작 시 한 번 조회하고 선택 상태를 현재 화면 메모리에만 유지한다. 이 선택은 공고 요구사항이나 답변 평가 근거로 전송하지 않는다.

## AC (Given-When-Then)

- **AC-01** GIVEN 로그인한 사용자가 채팅을 시작함, WHEN NCS API가 정상 응답함, THEN 지식·기술·태도 각 3개를 하나의 코치 메시지에서 선택할 수 있다.
- **AC-02** GIVEN 항목을 선택함, WHEN `선택 완료`를 누름, THEN 선택한 항목만 현재 채팅의 사용자 메시지에 표시된다.
- **AC-03** GIVEN 키 누락·제공자 실패·응답 형식 오류, WHEN 채팅을 시작함, THEN 허구의 NCS 항목 없이 오류와 재시도 동작을 보여 주고 공고 검색은 계속 가능하다.
- **AC-04** GIVEN 제공자가 다른 직무 또는 과거 차수의 행을 반환함, WHEN 서버가 응답을 만들 때, THEN 그 행을 선택지 근거에서 제외한다.
- **AC-05** GIVEN 로그아웃 사용자, WHEN 채팅을 열 때, THEN NCS API 호출 없이 로그인 안내만 표시한다.
