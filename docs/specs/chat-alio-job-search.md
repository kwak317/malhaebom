# 채팅 기반 ALIO 공고 선택·AI 분석

## Why

- 사용자는 대화 입력으로 개발 직무 또는 JD 관련 공고를 찾고, 선택한 공고의 요구사항을 면접 연습 맥락에 연결하고 싶다.
- 기존 ALIO 검색·원문 분석 API는 있으나, 전체 화면 채팅 UI의 입력·선택 흐름과 연결되어 있지 않다.

## Goal

- 로그인 사용자가 `개발 공고 보여줘`, `JD 보여줘`처럼 입력하면 ALIO 진행 공고를 대화 안에서 최대 10개 고른다.
- 공고를 고르면 `google/gemini-3.5-flash-lite` 설정의 분석 모델이 공개 HTTPS 원문에서 근거가 있는 요구사항만 추출해 저장한다.
- 사용자가 고른 요구사항 1~2개는 기존 연습 세션과 이후 코칭 문맥에 그대로 전달한다.

## What

1. 채팅 입력에서 공고 요청을 인식해 안전한 검색어를 정하고, FastAPI의 기존 ALIO 검색 API를 호출한다.
2. 결과를 채팅 말풍선 안의 선택 카드로 표시한다. ALIO 키는 FastAPI 서버 밖으로 나가지 않는다.
3. 사용자가 하나를 선택하면 기존 원문 분석 API를 호출한다. 분석 중에는 코치가 입력 중인 점 3개 효과를 표시한다.
4. 분석이 끝나면 원문 근거가 있는 요구사항을 채팅에서 1~2개 선택하게 하며, 기존 `create_practice_session`과 코칭 컨텍스트를 사용한다.

## How

- 새 DB 테이블·migration은 만들지 않는다. 기존 사용자 소유 ALIO 공고, RLS, `create_practice_session` RPC와 코칭 컨텍스트 조회 계약을 유지한다.
- ALIO 검색은 LLM이 직접 외부 키를 보유하거나 호출하지 않는다. 브라우저 요청은 Bearer JWT만 보내고, FastAPI가 서버 환경변수의 `ALIO_API_KEY`로 조회한다.
- 원문 분석 모델은 `JOB_REQUIREMENT_ANALYSIS_LLM_MODEL`을 우선 사용하고, 이 작업에서는 `google/gemini-3.5-flash-lite`로 설정한다. 원문에 없는 근거는 저장하지 않는다.
- 검색·원문 분석 요청 중에는 `aria-live` 상태를 가진 입력 중 말풍선을 표시한다. 실패하면 같은 대화 영역에 재시도 가능한 오류를 표시한다.

## AC

- **Given** 로그인 사용자가 `개발 관련 공고 보여줘` 또는 `JD 보여줘`를 입력한다. **When** 전송한다. **Then** 입력 중 효과 뒤 ALIO 검색 결과와 공고 선택 버튼이 대화 안에 표시된다.
- **Given** 사용자가 HTTPS 원문이 있는 공고를 선택한다. **When** 분석을 요청한다. **Then** 입력 중 효과 뒤 원문 근거가 포함된 요구사항만 표시·저장된다.
- **Given** 분석한 공고의 요구사항 1~2개를 고른다. **When** 기존 연습을 시작한다. **Then** 기존 세션 생성과 코칭 컨텍스트가 그 요구사항 ID를 사용한다.
- **Given** 외부 검색 또는 분석에 실패한다. **When** 요청이 끝난다. **Then** 키·원문·비밀값을 노출하지 않고 채팅에서 실패 안내를 표시한다.
