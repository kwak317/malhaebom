# ALIO LLM 원문 분석 기반 연습 맥락 Spec

## Why

- **페르소나**: 실제 공공기관 채용공고를 기준으로 프로젝트 문제 해결 면접을 연습하려는 신입 백엔드 개발자 준비생
- **상황**: 공고 검색 결과는 제목·기관명·원문 링크만 제공하므로, 제목으로 요구사항을 추정하면 공고에 없는 조건을 만들어 낼 위험이 있다.
- **문제**: 사람이 원문을 읽고 요구사항과 근거를 입력하면 코칭 시작 전 수작업이 남고, 사용자가 적은 표현에 따라 코칭 문맥이 달라진다.
- **측정 지표**: LLM이 원문에 실제 존재하는 근거 문구를 포함한 요구사항 1개 이상을 저장한 뒤, 해당 공고와 요구사항 1~2개가 고정된 연습 세션을 만들 수 있다.

## Goal

- 로그인 사용자가 ALIO 검색 결과에서 `AI 분석하고 요구사항 선택`을 누르면, 서버가 공개 HTTPS 원문을 가져와 LLM으로 요구사항·원문 근거를 1~5개 구조화해 저장한다.
- AI 분석 완료된 ALIO 공고와 요구사항 1~2개를 선택한 뒤 기존 문제 해결 질문·1차 녹음 흐름으로 이동한다.
- AI 분석한 ALIO 공고와 요구사항은 해당 사용자만 조회·연습 세션 생성할 수 있다.
- **Out of Scope**: 비-HTTPS 원문, JavaScript 렌더링 뒤에만 존재하는 본문, 팀 공용 공고, 공고 요구사항을 사용한 LLM 내용 코칭 변경, 2차 답변 비교 변경.

## What

### Happy Path

1. 로그인 사용자가 ALIO에서 공고를 검색하고 `AI 분석하고 요구사항 선택`을 누른다.
2. 서버는 공개 HTTPS 원문만 가져오며, 내부망 IP·리디렉션·1MB 초과 본문·비텍스트 응답을 거부한다.
3. LLM은 원문에 명시된 자격요건·우대사항·직무상 기대 역할만 1~5개 JSON으로 반환한다. 각 근거는 원문에 실제 존재하는 연속 인용이어야 하며, 서버가 다시 포함 여부를 검증한다. 검증 실패 시 한 번 재시도한다.
4. 서버는 분석 결과를 사용자 소유의 `reviewed` 공고·요구사항으로 원자적으로 저장한다. UI는 새 AI 분석 공고를 선택하고, 사용자는 요구사항 1~2개를 고른 뒤 기존 질문 선택·마이크·1차 답변 흐름을 시작한다.

### Edge Case

| 상황 | 처리 방식 |
| --- | --- |
| 원문 URL이 없거나 HTTPS가 아님 | AI 분석을 시작하지 않고 안내를 표시한다. |
| LLM 근거 문구가 원문에 없음 | 저장하지 않고 한 번 재시도한 뒤 오류를 표시한다. |
| 이미 같은 사용자가 같은 ALIO 공고를 분석 완료함 | 기존 AI 분석 공고를 선택하도록 안내하고 중복 저장하지 않는다. |
| 다른 사용자가 ALIO 분석 공고 ID를 추측 | RLS와 세션 RPC가 조회·세션 생성을 거부한다. |
| 로그인·세션 만료 | 기존 로그인 안내를 표시하며 분석 공고를 저장하지 않는다. |

## How

- 기존 `job_postings`와 `job_requirements`를 재사용한다. ALIO 분석 레코드는 `data_origin='alio'`, `review_status='reviewed'`, `reviewed_by_user_id`를 가진다. `reviewed`는 사용자 수동 검토가 아니라 원문 근거 검증을 통과한 AI 분석 결과라는 저장 상태다.
- ALIO 요구사항에는 LLM이 반환하고 서버가 원문 포함 여부를 검증한 `source_excerpt`를 보관한다. 더미·기존 공고의 해당 필드는 `null`을 허용한다.
- Supabase `review_alio_recruitment` RPC만 ALIO 분석 공고·요구사항을 만들 수 있다. 함수는 로그인한 비익명 사용자와 1~5개의 비어 있지 않은 요구사항·근거 문구를 검증하고 호출자 ID를 소유자로 저장한다.
- `data_origin='alio'` 레코드는 소유자만 보며, 기존 `reviewed`·`demo` 공고의 조회 정책은 바꾸지 않는다. `create_practice_session`도 ALIO 레코드의 소유자를 다시 검사한다.
- FastAPI `POST /api/alio/recruitments/analyze`는 사용자 JWT로 원문 추출·LLM 구조화·원문 근거 검증을 수행한 뒤 RPC를 호출한다. 브라우저는 ALIO API key, LLM key, Supabase service role key를 받지 않는다.
- LLM 호출은 서버의 `JOB_REQUIREMENT_ANALYSIS_*` 또는 기존 `COACHING_*` 비공개 설정을 사용한다. 원문 내용은 해당 모델 제공자에게 전달될 수 있다.

## AC

- **Given** 로그인 사용자가 HTTPS 원문 URL이 있는 ALIO 검색 결과를 고른다. **When** AI 분석을 요청한다. **Then** 서버는 원문 근거가 포함된 요구사항만 `alio` 공고와 요구사항으로 만들고 UI에서 즉시 선택할 수 있다.
- **Given** LLM이 원문에 없는 근거 문구를 반환한다. **When** 분석 결과를 검증한다. **Then** 서버는 저장하지 않고 재시도 후 실패를 표시한다.
- **Given** 사용자 A가 AI 분석 완료한 ALIO 공고가 있다. **When** 사용자 B가 카탈로그 조회 또는 그 공고로 연습 세션 생성을 시도한다. **Then** 공고를 읽거나 세션을 만들 수 없다.
- **Given** AI 분석 완료 공고를 고르고 요구사항 1개를 선택했다. **When** 기본 질문을 고르고 시작한다. **Then** 기존 `create_practice_session`을 통해 공고·요구사항·질문이 고정된 1차 답변 연습 세션이 생성되고, 이후 코칭 문맥은 해당 선택 요구사항을 조회한다.
