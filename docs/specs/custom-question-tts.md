# 기능 Spec — 사용자 입력 면접 질문 TTS

## Why

- **페르소나**: 정해진 질문뿐 아니라 자신이 준비한 면접 질문으로 반복 연습하려는 한국어 취업준비생
- **상황**: 사용자가 질문을 입력한 뒤, 답변 녹음을 시작하기 전에 질문자 음성을 기다린다.
- **문제**:
  1. 완성 WAV가 만들어질 때까지 기다리면 질문 재생 시작이 늦어진다.
  2. 짧은 질문에서 모델이 문장 뒤 무음·잡음을 계속 생성할 수 있다.
  3. 질문의 끝음절이 미세하게 잘리면 실제 면접 같은 흐름이 깨진다.
- **측정 지표**: 첫 음성 조각 수신 지연시간, 생성·재생 성공률, 종료 게이트 작동 여부, 사람 청취 검수 결과

## Goal

- **해결 목표**: 사용자가 공백 제외 1~200자 길이의 면접 질문을 입력하면, 서비스가 승인된 질문자 모델의 음성을 스트리밍으로 재생하고 답변 녹음으로 이어진다.
- **성공 기준**: 일반 길이 질문의 95% 이상이 요청 후 5초 이내 첫 `audio` 이벤트를 수신 / 유효 요청의 생성 성공률과 재생 성공률 각각 95% 이상 / 정상 완료된 WAV는 24 kHz·mono·PCM_16이며 마지막 음절 완결·잡음·자연스러움 청취 검수를 통과
- **Out of Scope**: 사용자 음성 복제, 입력 질문의 TTS 학습·파인튜닝 활용, 질문의 정답성·면접 적합성 평가, LLM 기반 질문 생성·변형·검수, 음성 파일의 영구 보관·공유, 코치 피드백 런타임 TTS의 구현

## What

**경계**

이 Spec은 사용자가 직접 입력한 질문의 실시간 합성만 다룬다. 기본 질문은 검수 완료된 사전 생성 WAV만 재생하며 [TTS 사전 생성 피드백 템플릿 Spec](tts-사전생성-피드백템플릿.md)을 따른다. 분석 LLM 기반 코치 피드백의 실시간 합성은 [분석 결과 코치 피드백 TTS Spec](coach-feedback-tts.md)에서 별도로 정한다.

**Happy Path**

1. 사용자가 직접 질문을 입력한다.
2. 프런트엔드는 Bearer JWT와 함께 `POST /api/questions/tts/stream`을 호출한다.
3. 백엔드는 입력값을 검증하고 정규화한 원문에 내부 전용 접미사 `//`를 붙여 승인된 질문자 모델에 전달한다.
4. 백엔드는 `start` 이벤트 뒤 24 kHz·mono·PCM16 음성 조각을 `audio` 이벤트로 순서대로 전송한다.
5. 프런트엔드는 Web Audio API로 첫 조각부터 이어 재생한다.
6. 실제 발화 뒤 저에너지 구간이 0.5초 연속되면 백엔드는 생성기를 닫아 긴 무음·잡음 생성을 막는다.
7. 정상 종료된 조각으로 전체 WAV를 만들고 비공개 Storage에 저장한 뒤, `complete` 이벤트로 `audioUrl`·길이·만료 시각을 전송한다.
8. 프런트엔드는 재생 완료 또는 사용자의 시작 동작 후 답변 녹음을 시작한다.
9. 스트리밍을 시작할 수 없는 클라이언트는 기존 완성-WAV API를 사용한다. 기존 API도 같은 내부 전용 접미사 규칙을 적용한다.

**Edge Cases**

| # | 상황 | 처리 방식 |
| --- | --- | --- |
| EC-01 | 빈 문자열·공백만 입력 또는 공백 제외 200자 초과 | `400 Bad Request`, 모델 호출·파일 생성 없음 |
| EC-02 | HTML 태그, 제어 문자 또는 null byte 포함 | `400 Bad Request`, 모델 호출·파일 생성 없음 |
| EC-03 | 모델을 시작하지 못함 | `503 Service Unavailable`, 공식 기본 화자로 대체하지 않음 |
| EC-04 | 스트림 시작 전 모델 생성 실패 | `503 Service Unavailable`, 파일·메타데이터 없음 |
| EC-05 | 스트림 시작 후 모델 생성 실패 | `error` 이벤트 전송 후 종료, 완성 WAV·메타데이터 없음 |
| EC-06 | 0.5초 저에너지 구간 감지 | 종료 게이트로 생성기를 닫고 이미 생성된 조각만 정상 완료 후보로 사용 |
| EC-07 | 최대 생성 한도에 도달했으나 정상 종료·종료 게이트가 없음 | `error` 이벤트 후 종료, 잘린 WAV·메타데이터 없음 |
| EC-08 | 사용자가 취소하거나 연결이 끊김 | 생성기를 즉시 닫고 메모리의 부분 음성·메타데이터를 저장하지 않음 |
| EC-09 | Storage 또는 DB 저장 실패 | `complete`를 보내지 않고 `error` 이벤트 전송, 업로드된 파일이 있으면 삭제 시도 |
| EC-10 | 음성 조각 순번 누락·중복 | 프런트는 재생 중단. 재생 시작 전이면 기존 완성-WAV API로 1회 폴백 가능 |
| EC-11 | 생성 WAV 만료 | 음성 조회 API에서 `404 Not Found` 반환 |

## How

### 기존 완성-WAV API와 폴백

```http
POST /api/questions/tts
Content-Type: application/json
Authorization: Bearer {accessToken}
```

- 기존 API는 삭제하거나 응답 형식을 바꾸지 않는다.
- 스트리밍을 지원하지 않거나 스트리밍 재생 시작 전 조각 순번 오류가 난 클라이언트만 이 API를 1회 사용한다.
- 이 API도 정규화 원문에만 내부 전용 접미사 `//`를 붙여 같은 승인 모델로 합성한다.

### 스트리밍 질문 음성 API

```http
POST /api/questions/tts/stream
Content-Type: application/json
Accept: application/x-ndjson
Authorization: Bearer {accessToken}

{
  "question": "협업 중 갈등을 해결한 경험을 말씀해 주세요."
}
```

- HTTP 상태를 아직 보낼 수 있는 입력 검증·인증·모델 시작 실패는 기존과 같이 `400`·`401`·`503`으로 응답한다.
- 정상 시작 응답의 Content-Type은 `application/x-ndjson; charset=utf-8`이다.
- 한 줄은 하나의 JSON 이벤트이며, 이벤트 순서는 `start` → `audio` 0개 이상 → `complete` 또는 `error`다. 정상 완료에는 `audio`가 1개 이상 있어야 하며, `complete`와 `error` 뒤에는 이벤트를 보내지 않는다.

`start` 이벤트:

```json
{
  "type": "start",
  "text": "협업 중 갈등을 해결한 경험을 말씀해 주세요.",
  "format": "pcm_s16le",
  "sampleRate": 24000,
  "channels": 1
}
```

`audio` 이벤트:

```json
{
  "type": "audio",
  "sequence": 0,
  "pcmBase64": "..."
}
```

- `sequence`는 0에서 시작하는 연속된 정수다.
- `pcmBase64`는 비어 있지 않은 PCM16 little-endian mono 조각이다.

`complete` 이벤트:

```json
{
  "type": "complete",
  "audioUrl": "/api/audio/questions/{audioId}",
  "durationMs": 4200,
  "expiresAt": "2026-08-20T15:22:10+09:00"
}
```

`error` 이벤트:

```json
{
  "type": "error",
  "code": "TTS_GENERATION_FAILED",
  "message": "질문 음성을 만들지 못했습니다. 다시 시도해 주세요."
}
```

### 질문 음성 조회 API

```http
GET /api/audio/questions/{audioId}
Authorization: Bearer {accessToken}
```

- 성공 시 소유자에게만 `audio/wav` 형식의 전체 WAV를 반환한다.
- 파일이 없거나 만료됐거나 소유자가 다르면 `404 Not Found`를 반환한다.

### 모델·재생·종료 규칙

- 팀이 비교·선정하고 라이선스를 확인한 로컬 질문자 모델만 사용한다. 공식 기본 화자·자동 화자 대체는 허용하지 않는다.
- `QUESTION_TTS_MODEL_PATH`가 있으면 FastAPI 프로세스가 로컬 GPU 모델을 로드한다. 값이 없으면 `TTS_WORKER_URL`의 별도 GPU Worker를 사용하되 FastAPI가 입력 검증, 소유권, 비공개 저장과 만료를 계속 담당한다.
- 로컬 모드는 서버 시작 시 모델을 한 번만 로드하고 내부 워밍업을 수행한다. Worker 모드는 시작 시 health를 확인하며 Worker가 모델 로드와 워밍업을 담당한다.
- 정규화 원문 뒤에 공백 없이 정확히 `//`만 붙인 문자열을 모델 입력으로 사용한다. 응답 텍스트·DB·로그·파일명·학습 데이터에는 접미사를 넣지 않는다.
- 로컬 모델은 결정적 설정(`do_sample=False`)으로 합성한다. 원격 Worker의 합성 설정은 배포 단위로 고정하고 비교 리포트에 버전을 기록한다.
- 생성 조각은 즉시 PCM16으로 변환해 전송하고, 서버 메모리에만 누적한다. 프런트는 Web Audio API로 순번대로 예약 재생하며 음성 Blob·TTS URL을 `sessionStorage`에 저장하지 않는다.
- 실제 음성 조각이 한 번 이상 전송된 뒤 RMS가 -35 dB 이하인 구간이 0.5초 연속되면 종료 게이트를 적용한다. 이 규칙은 인위적인 뒤쪽 무음을 추가하지 않는다.
- 정상 종료 또는 종료 게이트로 끝난 경우에만 누적 조각을 24 kHz·mono·PCM_16 WAV로 만들 수 있다. 최대 생성 한도만으로 끝난 결과는 정상 완료가 아니다.

### 입력 검증·보관·취소

- 앞뒤 공백을 제거한 뒤, 공백을 제외한 길이가 1~200자 범위인지 검사한다.
- 질문 텍스트를 로그에 원문 그대로 기록하지 않고, 추론·전송·정규화 외 학습 데이터로 저장하지 않는다.
- 정상 완료 때만 예측 불가능한 UUID로 WAV와 최소 메타데이터를 식별한다.
- 생성 시점부터 24시간이 지나면 WAV와 메타데이터를 함께 삭제한다.
- 클라이언트 취소·연결 해제·실패 시 생성기를 닫고 부분 WAV·메타데이터를 저장하지 않는다.

### 출시 전 검수

- GPU Worker에서 대표 직접 질문 13개를 스트리밍 방식으로 생성한다. 생성 WAV·상세 측정값은 Git에서 제외된 로컬 결과 폴더에만 둔다.
- 13개 결과마다 첫 `audio` 이벤트 수신 시간, 전체 생성 시간, 생성 성공 여부, 음성 길이, RTF, peak GPU memory, 종료 방식, WAV 형식, 사람 청취 검수 상태를 기록한다. 질문 원문·사용자 ID·모델 경로는 결과 기록에 넣지 않는다.
- 사람이 24 kHz/mono/PCM_16, 잡음, 마지막 음절 완결, 자연스러움을 확인해 `accepted` 또는 `rejected`로 남긴다.
- 일반 길이 질문의 95% 이상이 요청 후 5초 안에 첫 `audio` 이벤트를 수신하고, 생성 성공률·재생 성공률이 각각 95% 이상인 경우에만 앱 연결 후보로 판단한다. 기준 미달 시 원인을 기록하고 출시 후보로 주장하지 않는다.

## AC (Given-When-Then)

**AC-01 · 유효한 질문 스트리밍 시작**

- GIVEN: 인증된 사용자가 공백 제외 1~200자 길이의 질문을 입력했다.
- WHEN: `POST /api/questions/tts/stream`을 호출한다.
- THEN: 서버는 `start` 이벤트와 24 kHz·mono·PCM16 형식 정보를 먼저 전송하고, 0부터 연속된 `audio` 이벤트를 하나 이상 전송한다.

**AC-02 · 내부 접미사와 원문 분리**

- GIVEN: 유효한 질문이 정규화됐다.
- WHEN: 서버가 모델 합성을 시작한다.
- THEN: 모델은 원문 뒤에 공백 없는 `//`가 붙은 문자열만 입력으로 받고, `start.text`·`complete`·DB·로그에는 접미사가 없는 원문만 사용된다.

**AC-03 · 첫 음성 지연시간**

- GIVEN: 서버가 모델 로드와 짧은 내부 워밍업을 마쳐 준비 상태다.
- WHEN: 일반 길이 질문 13개 검수 세트를 스트리밍 요청한다.
- THEN: 95% 이상에서 요청 시점부터 첫 `audio` 이벤트 수신까지 5초 이내이며 측정값을 로컬 검수 기록에 남긴다.

**AC-04 · 종료 게이트**

- GIVEN: 실제 음성 조각이 전송된 뒤 RMS가 -35 dB 이하인 구간이 0.5초 연속됐다.
- WHEN: 서버가 다음 생성 여부를 판단한다.
- THEN: 서버는 생성기를 닫고 인위적 뒤쪽 무음 없이 이미 생성된 조각만 정상 완료 후보로 사용한다.

**AC-05 · 취소·연결 해제**

- GIVEN: `start` 또는 `audio` 이벤트 뒤 사용자가 재생을 취소하거나 연결이 끊겼다.
- WHEN: 서버가 연결 해제를 감지한다.
- THEN: 생성기를 닫고 부분 WAV·Storage 파일·DB 메타데이터를 남기지 않는다.

**AC-06 · 스트림 중 실패와 저장 실패**

- GIVEN: 스트림 시작 뒤 모델 생성, Storage 업로드 또는 DB 기록이 실패했다.
- WHEN: 서버가 실패를 처리한다.
- THEN: `error` 이벤트로 종료하고 `complete`를 보내지 않으며, 업로드된 부분 파일은 삭제를 시도하고 완성 WAV·메타데이터를 남기지 않는다.

**AC-07 · 기존 완성-WAV API 폴백**

- GIVEN: 클라이언트가 스트리밍을 지원하지 않거나 재생 시작 전 조각 순번 오류를 감지했다.
- WHEN: 클라이언트가 기존 `POST /api/questions/tts`를 1회 호출한다.
- THEN: 기존 JSON 응답 형식과 `audioUrl` 계약은 유지되고, 같은 내부 전용 `//` 접미사 규칙으로 생성된 완성 WAV를 반환한다.

**AC-08 · 음성 파일 재생·만료**

- GIVEN: 스트리밍이 `complete` 이벤트로 정상 종료됐다.
- WHEN: 소유자가 `audioUrl`을 요청한다.
- THEN: 서버는 비어 있지 않은 24 kHz·mono·PCM_16 `audio/wav`를 반환하며, 생성 24시간 뒤 정리 작업이 실행되면 WAV·메타데이터를 삭제하고 이후 요청은 `404 Not Found`를 반환한다.

**AC-09 · 공식 화자 폴백 금지**

- GIVEN: 승인된 로컬 질문자 모델을 시작하거나 생성하는 데 실패했다.
- WHEN: 스트리밍 또는 기존 완성-WAV API를 호출한다.
- THEN: 서버는 공식 기본 화자·다른 화자로 대체하지 않고 `503` 또는 `error`로 실패를 알린다.
