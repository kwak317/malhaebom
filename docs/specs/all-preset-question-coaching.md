# 기본 질문 전체 코칭

## Why

화면에서는 기본 질문 10개를 선택할 수 있으나 `/api/agent`와 MCP 질문 저장소가 `preset-04`만 허용해 다른 질문은 코칭되지 않는다. 사용자 요청에 따라 기존 화면의 10개 질문으로 지원 범위를 확장한다.

## Goal

- `preset-01`~`preset-10` 모두 확인된 답변을 질문에 맞는 기준으로 코칭한다.
- 4번의 여섯 문제 해결 기준과 기준 버전은 유지한다.
- Out of Scope: 직접 입력 질문, 자료에만 있는 11~60번 추가 노출, 평가셋·mock·프롬프트 제출자료 변경, 합격·전체 역량 판정.

## What

공고·요구사항과 질문을 선택하고 녹음·전사 확인 후 기존 `/api/agent`를 호출하면 질문별 판정·인용·확인 질문·다음 행동·예시 답변을 받는다. 재답변은 같은 질문·기준으로 비교한다. 알 수 없는 질문은 기존 `unsupported` 응답으로 처리한다.

## How

- 기존 `configs/feedback/question-rubrics.json`의 화면 기본 질문 10개와 개념 ID를 서버 질문 카탈로그로 사용한다.
- Skill에 기본 면접 질문 기준을 추가하고 질문 유형별 기준 버전을 검증한다. 문제 해결 질문은 기존 카탈로그와 버전을 사용한다.
- 자기소개·지원동기 등의 답변에는 문제 해결 전용 기준을 적용하지 않는다.
- API 입력·출력 계약, 인증·소유자·만료·인용 검증, MCP 도구 수, 모델 호출 횟수 제한은 유지한다. DB migration은 필요 없다.
- 새 기준의 한국어 이름을 코칭·비교 화면에 표시한다. 신규 규칙은 팀 초안이며 외부 검토 완료로 표시하지 않는다.

## AC

1. Given 기본 질문 10개, When 서버 질문 문맥을 조회하면, Then 질문 본문과 해당 기준·버전이 Skill 검증을 통과한다.
2. Given 1~3·5~10번, When 코칭하면, Then MCP와 LLM을 호출하고 문제 해결 전용 기준을 요구하지 않는다.
3. Given 4번, When 코칭하면, Then 기존 여섯 기준과 `problem-solving-v4-draft.3`을 유지한다.
4. Given 등록되지 않은 질문, 다른 사용자·만료 답변, 질문 불일치 또는 잘못된 기준, When 요청하면, Then LLM 호출 전에 차단한다.
5. Given 새 기준 응답, When 코칭·전후 비교를 표시하면, Then 기준을 한국어 이름으로 구분한다.
6. 기존 backend·frontend 테스트와 frontend build가 통과한다. 실행 서버 적용과 실제 외부 모델 호출은 별도 증거로 기록한다.
