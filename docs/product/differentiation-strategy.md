# 말해봄 에이전트 차별화 전략

> **문서 역할:** 말해봄의 제품 차별화 방향과 경쟁 서비스 대비 포지셔닝을 정리한다.  
> **현재 MVP 범위:** 현재 구현에는 공고 원문 조회, LLM 요구사항 추출, 서버 원문 근거 검증과 공고 저장 경로가 포함된다. 코칭에는 검증·저장된 공고 snapshot과 사용자가 선택한 요구사항만 사용한다. 실제 로그인 사용자 흐름과 배포 환경의 전체 검증은 별도로 확인해야 한다. 현재 구현 상태는 [CURRENT_STATE](../CURRENT_STATE.md), 목표·범위는 [TARGET_STATE](../TARGET_STATE.md)와 [CONSTRAINTS](../CONSTRAINTS.md), 구현 계약은 [PRD](../prd.md)와 각 기능 Spec을 따른다.


## 핵심 정의

현재 말해봄의 핵심은 **검토된 공고 요구사항과 실제 답변 원문을 연결해 근거 기반으로 코칭하고, 같은 기준으로 재답변의 변화를 확인하는 것**이다.

연습 준비 단계에는 **공고 원문 조회 → LLM 요구사항 추출 → 서버 원문 근거 검증 → 공고 저장 → 사용자 요구사항 선택** 경로가 구현되어 있다. 요구사항 추출 규칙은 `skills/job-requirement-extraction/SKILL.md`, 분석과 검증은 `backend/app/services/alio_requirement_analysis.py`에서 확인할 수 있다.

```text
[현재 구현 흐름]
공고 원문 조회
→ LLM이 요구사항 + 원문 근거 후보 추출
→ 서버가 출력 형식과 원문 인용 검증
→ 검증된 공고 snapshot과 요구사항 저장
→ 사용자가 연습할 요구사항 1~2개 선택
→ 답변·음성 분석 및 근거 기반 코칭
→ 같은 기준으로 재답변 비교
```

현재 차별화 가설은 **사용자 선택권 + 답변 원문 근거 추적 + 동일 기준 재답변 비교**에 있다. 공고 원문 분석은 연습에 사용할 요구사항을 준비하는 현재 기능이다.

## 일반 AI 면접 에이전트와의 차이

| 항목 | 일반 AI 면접 에이전트 | 말해봄 에이전트 |
| --- | --- | --- |
| 공고 이해 | 공고 제목·URL·사용자 입력을 바탕으로 질문 생성 | LLM이 원문에서 요구사항 후보를 추출하고, 검증·저장된 요구사항을 코칭에 사용 |
| 공고 신뢰성 | AI 해석 결과가 왜 나왔는지 불명확할 수 있음 | LLM 추출 근거의 원문 일치를 서버가 검증하고, 저장된 snapshot을 코칭에 사용 |
| 사용자 역할 | AI가 만든 질문을 바로 연습 | 분석된 요구사항 중 사용자가 연습할 기준 1~2개 선택 |
| 코칭 기준 | 전반적인 “좋은 답변” 기준 | 선택 요구사항 + 문제 해결 기준 + 실제 답변 문장 |
| 피드백 근거 | 추상적 요약이나 점수 중심 | 답변의 어느 문장이 어떤 기준을 충족·보완하는지 표시 |
| 학습 흐름 | 한 번 답변 → 리포트 | 1차 답변 → 코칭 → 재답변 → 동일 기준 비교 |
| 데이터 관리 | 대화 단위 기록 중심 | 공고 스냅샷·요구사항·전사문 revision·코칭 결과를 연결 |

## 백엔드 관점에서의 진짜 차별점

### 1. 자유로운 챗봇이 아닌, 통제된 근거 기반 코칭 에이전트

LLM이 공고 원문에서 추출한 요구사항은 출력 형식과 원문 인용 검증을 통과한 뒤 저장한다. 코칭 문맥에는 저장된 공고 snapshot과 사용자가 선택한 요구사항만 전달한다.

```text
LLM 요구사항 추출 → 서버 원문 검증 → 공고 snapshot 저장
→ 사용자 요구사항 선택 → 서버가 연습 세션에 고정
```

원문 인용 검증은 출처 일치를 확인하는 절차다. 추출한 요구사항의 의미가 모두 정확하거나 기업의 실제 면접 기준과 같다는 것을 보장하지는 않는다.

### 2. 공고 기반 코칭의 기준이 흔들리지 않음

사용자가 선택한 요구사항은 연습 세션에 고정됩니다.

```text
선택 공고
+ 선택 요구사항
+ 선택 질문
+ 확정 전사문
= 해당 답변의 코칭 기준
```

그래서 다음 답변에서도 “무슨 기준으로 부족하다고 했는지”가 바뀌지 않고, 재답변 비교가 가능합니다.

### 3. 피드백이 아닌 근거 추적

말해봄은 다음 질문에 답할 수 있어야 합니다.

- 이 피드백은 선택한 공고의 어떤 요구사항 때문인가?
- 답변의 어느 문장이 근거인가?
- `충족`, `일부 보완 필요`, `확인되지 않음` 중 어디에 해당하는가?
- 다음 답변에서는 무엇을 말해야 하는가?

이 구조가 없다면 AI 피드백은 그럴듯한 조언에 머물 수 있습니다.

### 4. 선택권이 있는 개인화

원문 분석과 서버 검증을 거쳐 저장된 요구사항 중 사용자가 선택한 1~2개를 코칭에 사용합니다.

사용자는 예를 들어 아래 중 이번 연습 목표를 직접 선택합니다.

```text
- 백엔드 개발 경험
- API 설계·문제 해결 경험
- 협업 경험
- 데이터베이스 활용 경험
```

따라서 말해봄은 “공고를 자동 요약하는 AI”가 아니라, **사용자가 선택한 목표에 맞춰 연습을 집중시키는 AI 코치**가 됩니다.

## 발표용 문구

> 현재 말해봄은 검토된 공고 요구사항과 실제 답변 문장을 연결해 근거와 보완점을 보여주고, 같은 질문의 재답변에서 무엇이 달라졌는지 확인하는 면접 학습 에이전트입니다.

> 경쟁 서비스가 면접 결과를 진단하는 데 집중한다면, 말해봄은 사용자가 선택한 공고 요구사항을 기준으로 답변을 수정하고 재연습할 수 있는 개선 과정을 제공합니다.

> 현재 공고 분석 단계에서는 LLM이 원문에서 요구사항과 인용 근거를 추출하고 서버가 이를 검증합니다. 저장된 요구사항 중 사용자가 선택한 항목을 답변 코칭에 연결합니다.

## 과장하지 않아야 할 부분

다음은 이미 경쟁사도 제공하거나 내부 구현이 공개되지 않아 독점 기능처럼 말하면 안 됩니다.

- AI 공고 분석
- 공고 맞춤 질문
- 음성·영상 면접 연습
- 꼬리질문
- 예시 답안
- 말하기 속도·표정 분석
- 결과 리포트

현재 MVP에서는 아래 조합을 차별화 가설로 내세우는 것이 정확합니다.

> **LLM 공고 원문 분석 + 서버 근거 검증 + 사용자 요구사항 선택 + 답변 문장 기반 코칭 + 재답변 비교**

이 조합의 실제 사용자 효과와 배포 환경의 전체 흐름은 추가 검증이 필요하다. 장기적으로는 면접관 검토 데이터를 더해 어떤 코칭이 실제 답변 개선으로 이어졌는지 검증 가능한 기록을 축적한다.
